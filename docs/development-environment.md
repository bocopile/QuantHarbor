# 개발 AI 환경 — ENV 실행 기준

기준일: 2026-10-20. 현재 단계는 ENV이며 투자 애플리케이션 구현 전이다. 설정 파일 작성·배치와 클라이언트 로드·동작 확인을 구분한다. 초기 상태는 [착수 카드](tasks/ENV-bootstrap.md), 후속 설정 조회 결과는 [도구·권한 카드](tasks/ENV-controls.md)를 따른다. 최신 팀 구성 요청에 따라 [orchestrator와 전문 역할 6개](ai-team.md)가 활성 worker 한 명씩 순차 수행한다.

## 작업공간과 정보 경계

| 위치 | 책임·내용 |
|---|---|
| `AGENTS.md` | 시작 순서·권한·변경·인계 규칙 |
| `.codex/config.toml`, `.codex/agents/` | 프로젝트 역할·위임 상한·MCP 도구 목록·앱 기본 제한·선택형 권한 프로필. 주 담당 관리 |
| `.codex/hooks.json` | 소스 해시를 고정한 감사 Hook 6종. 신뢰 검토 필요 |
| `.agents/skills/qh-*/SKILL.md` | 프로젝트 인계·결정·계약 변경 절차 |
| `config/ai/development-policy.toml` | 버전 있는 작업 정책. Codex가 자동 강제하는 설정이 아님 |
| `docs/tasks/`, `docs/decisions/` | 비민감 작업 카드·결정 기록. 공통 상태는 주 담당이 통합 |
| 저장소 밖 운영 영역 | 키·계좌·거래·개인 보고·로그·DB·백업. 경로·제품 미정, 아직 생성하지 않음 |

현재 세션은 호스트가 관리하는 workspace-write 환경이다. `.codex`·`.agents` 같은 보호 경로의 설정 배치는 해당 쓰기 권한 절차를 따른다. 전역 설정·인증·원격 저장소·기존 변경은 수정하지 않는다. worktree나 폴더 분리만으로 운영정보가 격리됐다고 보지 않는다.

## 역할 계약

| 역할 | 입력 | 출력 | 수정 범위 |
|---|---|---|---|
| 주 담당 | 요청·상태·계약 | 계획, 변경 통합, 완료·인계 기록 | 요청 범위의 파일과 공통 계약 |
| `qh_researcher` | 탐색 범위·비교 질문·선택 기준 | 구조·파일/심볼·공식 출처·조건·미확인 | 없음 |
| `qh_architect` | 요구·공통 계약·의존성 | 설계·실패 경로·계약 변경 제안 | 없음; 주 담당 통합 |
| `qh_implementer` | 확정 계약·소유 파일 | 변경·확인·남은 위험 | 배정 파일; 공유 상태는 주 담당에게 반환 |
| `qh_reviewer` | 변경 버전·완료 기준 | 발생 조건·영향·근거 있는 결함 | 없음 |
| `qh_security_reviewer` | 변경·권한 경계 | 노출·승인·격리 문제와 강제 지점 | 없음 |
| `qh_validator` | 사용자가 요청한 검증 범위 | 명령·환경·결과·미실행 | 승인된 검증 산출물만; 대상 코드 임의 수정 없음 |

역할 파일의 읽기 중심 지침은 별도 읽기 전용 샌드박스가 아니다. direct subagent의 MCP와 provider·권한은 부모 세션에서 상속된다. 후속 ENV-DEC-004에서 제한이 필요한 역할 업무는 명시적인 별도 부모 프로필을 사용하도록 정했고 두 프로필 접근 경계·읽기 업무·MCP 노출을 확인했다. 현재 direct subagent 권한이 변경된 것은 아니다. 기존 qh_explorer 파일은 호환용으로 보존한다.

## 모델·비용·실패 정책

- 사용자 요청에 따라 역할별 모델·추론을 team.toml과 역할 파일에 명시한다. 새 프로젝트 기본값은 gpt-6.1-sol/high이며 실제 하위 위임에는 모델·추론을 직접 전달한다. 자동 상향·API 기반 추가 runner·스케줄러는 생성하지 않는다.
- 현재 계정에서 선택된 개발 세션을 사용한다. 모델 가격·성능·계정 가용성 확정은 ENV-04/B06의 후속 근거가 필요하다.
- 최초 설정 조회의 gpt-6-luna/high는 팀 구성 전 CLI 값이다. 이후 사용자 요청으로 프로젝트 기본을 변경했다. 어느 값도 현재 앱 대화 모델의 실측 증거로 취급하지 않는다.
- 2026-10-20 로컬 app-server `model/list`에서 선택 목록 7개와 지원 추론 수준을 확인했다. [목록 근거](evidence/env-model-catalog-2026-10-20.json)를 남겼다. picker 기본 표시는 gpt-6.1-sol이며 기존 설정값과 다른 개념이다. 실제 추론·가격·사용량 상한 확인은 수행하지 않았다.
- 현재 개발 팀은 기존 구독 범위만 사용하며 신규 지출·크레딧 구매·추가 유료 runner는 허용하지 않는다. 한도 도달 시 중단한다. [개발 비용 경계](tasks/ENV-development-budget.md)를 따르며, 정책 TOML로 계정 청구 상한을 강제한 것은 아니다. 향후 투자 운영의 월 예산·유료 자원은 별도 결정이다.
- 동일 실패는 원인과 재시도 조건을 기록한다. 주문·외부 변경에 일반 도구 재시도 규칙을 적용하지 않는다.
- `scripts/validate_environment.py`는 정책 파일의 명령별 15초·명령 묶음 120초·자동 재시도 0회를 읽어 강제한다. 해당 검증기만의 제한이며 모든 Codex 명령의 한도가 아니다. 추가 유료 runner 예산은 0으로 두고 생성하지 않는다.

## 도구 목록과 권한 상태

다음은 도구 사용 범위와 실제 설정 상태다. 전역 설정에서는 비민감 필드만 골라 읽었고 인증값은 출력하지 않았다. 프로젝트의 코드 탐색 MCP allowlist와 앱 기본 제한을 로컬 config/read에서 확인했다. 이 표 자체는 권한 강제 장치가 아니다.

| 도구 범주 | 현재 사용 범위 | 남은 구성 |
|---|---|---|
| codebase-memory-mcp | 현재 대화의 실제 도구 11개가 허용 목록과 일치, 그래프 조회 동작 | 다른 앱/역할별 권한은 별도 |
| GitHub 읽기·공식 웹 문서 | 공개 명세·소스·버전 근거; 앱 기본 외부 변경 제한 로드 | 개별 앱/도구 재정의와 역할별 노출 확인 |
| 로컬 파일·명령 | 배정 파일 수정, 비민감 상태·설정 확인 | 별도 읽기 전용 검토 세션/환경 확인 |
| Slack | AP-01 명시 승인, 비공개 채널 생성·합성 메시지 1건 전송/읽기 확인 | Q04 후 Q05 판정; 수동 개발 알림 범위이며 투자 보고·예약 실행 제외 |
| 증권사·자금 도구 | 개발 역할에 연결하지 않음 | ARC 이후 별도 실행 서비스 계약 |
| 유료 AI API | 새 호출 runner 없음 | 예산·권한·평가·사용량 기록 |

코드 탐색 도구 우선순위는 AGENTS.md를 따른다. 이미 노출된 외부 도구가 있다는 이유로 외부 변경 권한을 얻은 것으로 해석하지 않는다.

코드 탐색 allowlist에는 `search_graph`, `trace_path`, `get_code_snippet`, `query_graph`, `search_code`, `get_architecture`, `get_graph_schema`, `index_repository`, `index_status`, `list_projects`, `detect_changes`를 넣었다. 다른 전역 MCP와 앱 connector는 이 allowlist의 적용 대상이 아니다. 앱 기본 제한도 개별 앱/도구 설정과 도구 메타데이터에 따라 달라진다.

## 선택형 부모 권한 프로필

| 프로필 | 기본 경계 | 추가 설정 | 실제 상태 |
|---|---|---|---|
| qh_review | 기본 `:read-only` 확장 | 명령 네트워크 off, 지정 credential·운영 경로 deny | 검증 명령에서 선택, 5개 합성 검증 통과 |
| qh_development | 기본 `:workspace` 확장 | 동일 제한, 보호 설정 경로의 기존 read-only 유지 | 검증 명령에서 선택, 5개 합성 검증 통과 |

전역의 기존 sandbox_mode와 충돌하지 않도록 default_permissions는 설정하지 않았다. 검증 명령에는 `codex sandbox -P`로 명시 선택했으며 현재 앱 세션의 기본 프로필은 변경하지 않았다. 역할 파일의 이름에 따라 자동 적용되지 않는다. 명령 네트워크 off는 MCP·connector·브라우저·모델 통신까지 차단하는 설정이 아니다. 지정 경로 외의 모든 비밀정보를 탐지하거나 모든 파일 읽기를 막는다고 주장하지 않는다.

## Skills·Hooks·감사

- `qh-task-handoff`: 작업 착수·재개·종료와 실제 완료 기록.
- `qh-evidence-decision`: 확인 사실·설계 제안·미확인을 분리한 결정 기록.
- `qh-contract-change`: 공통 계약 버전·의존 작업·실패 처리·변경 영향.

각 Skill은 프로젝트 경로의 SKILL.md로 제공하며 일반 질의응답에 무조건 적용하지 않는다. 병렬 실행·테스트·외부 변경 권한을 추가하지 않는다. 현재 대화의 목록과 로컬 skills/list에서 3개 모두 발견됐으며 활성 상태·발견 오류 0을 확인했다. 후속 [ENV-skill-workflow](tasks/ENV-skill-workflow.md)에서 제한된 읽기 전용 부모 CLI가 세 Skill과 상태 문서를 실제로 읽고 합성 인계 10개를 분류했다. 이는 명시 Skill 적용의 성공이며 자동 선택·전체 대표 흐름 검증은 아니다.

기존 정적 SessionStart 안내를 [ENV-hook-audit](tasks/ENV-hook-audit.md)의 해시 고정 감사 정의 6종으로 확장했다. 시작·지원 도구 호출 전후·중단·종료의 고정 메타데이터만 저장소 밖 사용자 전용 임시 영역에 기록한다. 원시 명령·입출력·식별자·오류는 저장하지 않는다. 명시 결과 필드가 없는 도구 응답은 성공이 아닌 unknown이다.

클라이언트 hooks/list에서 6종 모두 enabled=true·untrusted, 오류·경고 0을 확인했다. 전용 합성 테스트 8개와 전체 테스트 55개는 통과했지만 사용자 신뢰와 실제 Hook 실행은 아직이다. `/hooks`에서 정의를 검토하며 자동 신뢰·우회 플래그를 사용하지 않는다. PreToolUse 기록 실패의 명시 deny는 지원 경로에만 적용된다. Hook 미지원 경로·시간 초과·플랫폼 누락을 포함한 전체 도구 통제나 금융 실행 권한을 대신하지 않는다.

[ENV-runtime-controls](tasks/ENV-runtime-controls.md)에서 검증기의 실행 ID·입력 해시·시도 횟수·소요 시간·결과를 남기는 완료 보고를 구현했다. 원시 출력은 제외한다. 정상 완료 시 생성하는 이 보고는 전체 도구 Hook 감사나 강제 종료에도 보존되는 로그를 대체하지 않는다.

후속 [ENV-durable-audit](tasks/ENV-durable-audit.md)에서 고정 로컬 검사 두 종류의 실행 전 start·종료 terminal 기록과 불완전 기록 판독을 구현했다. 전용 합성 테스트 16개, 기존 회귀 테스트 18개 및 실제 팀 검사·기록 조회를 독립 검증했다. 이 wrapper를 거치지 않는 도구 호출은 대상이 아니며 Hook 신뢰·전체 도구 감사와 구분한다.

## 작업과 인계

1. 작업 카드에서 선행조건·입력 버전·소유 파일·산출물·검증 범위를 확인한다.
2. 기존 사용자 변경을 보존하고 공통 계약·DB migration·상태 기록의 작성자는 한 명으로 둔다.
3. 상태는 대기→진행→검토 필요→완료로 기록한다. 미정 결정은 보류, 실행 오류는 실패로 남긴다.
4. 완료는 작성/설치/실제 로드/행동 검증을 구분한다. 자기 검토를 독립 검토로 표현하지 않는다.
5. 중단 시 재시작 입력·남은 결정·다음 행동을 카드와 status에 남긴다.

## ENV-11 대표 검증 — 일부 실행 완료

사용자의 전체 순차 실행 요청에 따라 합성 자료로 로컬 검증을 진행했다. 최초 ENV-validation은 단일 담당의 자기 검토이고, 이후 실제 팀 순차 실행·독립 검토는 [TEAM-bootstrap](tasks/TEAM-bootstrap.md)에 별도로 기록한다.

| 흐름 | 확인할 결과 |
|---|---|
| 프로젝트 설정·역할·Skill 발견 | 충돌 없이 `qh_` 역할 6개와 Skill 3개가 해당 프로젝트에서 보임 |
| 조사→결정 | 합성 요구·공개 출처로 사실/제안/미확인을 분리 |
| 변경→검토→인계 | 임시 합성 문서의 배정 변경, 근거 검토, 실제 결과/미실행 기록 |
| 재개 | 새 세션에서 카드·status만 읽고 다음 작업과 미완료를 식별 |
| Hook | 검토·신뢰된 시작/재개 안내만 실행, 외부 전송·민감 로그 없음 |
| 권한 | 선택한 부모 환경의 파일·도구 제한을 확인. 역할 지침만으로 격리를 통과 처리하지 않음 |

명령 프로필의 파일·네트워크 경계 10개는 당시 설정 버전에서 통과했다. 실제 MCP 목록도 확인 당시 설정과 일치했다. 최신 역할 실행 결과는 ENV-role-boundary와 ENV-DEC-004를 따른다. Slack 수신은 ENV-slack에서 확인했으며 전체 새 세션 재개·신뢰된 Hook 실행은 남아 있다. 컨테이너·실전 권한·금융 검증은 이 개발 흐름의 성공으로 완료되지 않는다.
