# Q07 요구 수용 기준과 정상·장애 시나리오

기준일: 2026-10-23 · 요구 계약 v1 — Q07 독립 검토 통과 · A-DEC-001~003 반영, 후속 운용값은 PG-01~05에서 확정. 제품 철학과 확정 입력에 따른 수용 계약이며, 구현·금융 검증·주문 실행 승인 문서가 아니다. [작업 카드](tasks/ARC-requirements.md), [확정 입력](requirements-input.md), [전체 작업](execution-checklist.md)을 함께 따른다.

## 요구의 출처와 범위

사용자가 확정한 요구는 한국·미국 개별 주식과 일반 ETF 초기 포함, 장중 반복 분석·주문 후보 생성, 사용자 수동 환전과 시스템 현금 조회다. 근거는 [A-DEC-001](decisions/A-DEC-001-initial-product-input.md)이다. 나머지 수용 기준은 아래의 검토된 계약이며 실제 검증은 후속 구현에서 수행한다.

[A-DEC-002](decisions/A-DEC-002-initial-trading-policy.md)에 따라 현금계좌·정규장만, 신용·공매도·레버리지·인버스 제외, 분석·후보 생성 기본15분, 모의우선·주문 후보마다 사용자 승인을 확정했다. 정확한 거래소·주문 유형·전략·위험 한도·운영 예산도 미정이다. 현재 실제 계좌 연결·주문·환전·예약 실행은 승인되지 않았다.

| REQ-08 | 제안에 출처·시점·가정·반대 근거와 미확인을 표시한다. 금액·위험·원장 계산은 결정론적 코드 검사를 통과해야 하며 AI 동의로 대체하지 않는다 | ARC-01 → F, G, H, J | 제품 철학 기반 제안, 모델 평가·계약 후속 |
| REQ-09 | 보고의 잠정/확정·기준 원장 버전·정정 관계·전달 결과를 표시한다. 거래 결과와 전달 실패를 분리한다 | A06 → J01~06, M01·02 | 수신자·전달 권한·보존 정책 미정 |

각 요구의 수용 여부는 후속 계약·합성 사례·통합 검증으로 확인한다. 아래 시나리오는 실행 결과가 아니라 검증할 기대 동작이다.

## 정책 관문과 완료 기준

사용자가 [A-DEC-003](decisions/A-DEC-003-policy-gates.md)의 세 권고안을 모두 채택했다. Q07 완료 기준은 A01 범위와 A02~06 정책 구조·필수 단위/계산 의미·책임·확정 시점·미설정 실행 거부, 위 요구9개와 시나리오16개의 수용 기준이다. 실제 자금·위험 수치·전략·지속 운영값 전체 완료를 뜻하지 않는다.

- A01: 한국·미국 현금계좌·정규장 개별 주식과 일반 ETF, 신용·공매도·레버리지·인버스 제외. Q08에서 거래소·상품 분류·정규장·모의/실전 지원 근거를 확인하고 후속 계약에서 공급자 코드를 매핑한다. 불명확·미지원 상품은 허용 목록에 넣지 않는다. 레버리지/인버스가 아니라는 이유만으로 일반 ETF로 인정하지 않는다. 기초자산 지역을 거래시장 범위와 혼동하지 않으며 모호한 상품군의 편입만 사용자에게 확인한다.
- A02·04·05: [PG-01](policy-gates.md)의 모의 API 전 자금·위험·승인 세부 정책과 PG-05 별도 실전 정책을 따른다. 후보별 승인은 정책 검사 면제가 아니다.
- A03: 분석 기본15분. PG-02에서 평가용 가정을 고정하고 PG-03에서 사용자가 비교안으로 전략·기간·리밸런싱을 선택한다.
- A06: 초기 사용자 시작/종료 로컬 모의 세션·신규 유료 비용0. 장애 시 신규 제출 중단·확인 후 수동 재개. 초기 기록·대사·복구 계약은 ARC에서 설계하고 지속 모의 전에 PG-04 운영 요구를 확정한다.

API 연결·평가·제출·지속 운용·실전 진입별 차단 조건과 실제 미완료 상태는 [정책 관문](policy-gates.md)을 따른다. 공급자 지원표·실제 금융값·실행 권한을 이 문서로 확보했다고 표시하지 않는다. Q07의 명시 범위는 독립 검토를 통과했다. 검토 당시 버전은 연결된 작업 카드의 증거에 보존한다.
