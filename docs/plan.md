# 전체 작업 계획

## 실행 순서와 상태

최상위 순서는 **ENV AI 제반환경 → ARC 요구사항·아키텍처 → 의존관계에 따른 구현 → 검증 → 모의·실전 운용**이다. A~M은 기능별 백로그이며 글자 순서가 최상위 실행 순서를 대체하지 않는다. A·B 중 설계 입력은 ARC에서 처리하고 이후 구현에 반영한다.

2026-10-20 상세화한 [전체 세부 작업과 순차 실행 준비사항](execution-checklist.md)에 이 계획의 **110개 ID 전체**, 작업별 세부 실행·산출물·완료 기준, **36개 실행 순서 묶음**, 단계별 사용자 준비사항을 정리했다. 현재 상태는 [진행 기록](status.md)과 작업 카드를 따른다.

아래 작업은 명시적으로 완료 표시한 경우를 제외하고 미착수다. 조사 자료가 존재해도 최종 선정·설치·검증이 완료된 것은 아니다.

- P0: 필수 작업. 실전 진입에 필요한 구현·검증은 소액 실전 전에 완료하고, L04처럼 실제 운용 결과가 필요한 항목은 해당 운용 단계에서 완료한다.
- P1: 사용자 개입을 줄인 전체 자동운영 전에 완료.
- P2: 운영 경험 확보 후 고도화.

각 작업은 작업 정의 → 설계 확인 → 구현 → 승인된 검증·검토 → 문서·인계 갱신 → 완료 판정을 따른다. 사용자 요청 없이 테스트를 추가하거나 실행하지 않는다. 병렬 작업은 사용자가 요청하고 인터페이스·소유권이 분리된 경우에만 진행한다.

현재 사용자는 전체 순차 실행과 필요한 로컬 합성 검증을 요청했다. 이 범위의 설정·작성·구현·검증·수정에는 단계별 진행 허가를 다시 묻지 않는다. 외부 전송·실제 계좌·자금·클라이언트 신뢰 조작 등은 정해진 대상·권한·사용자 결정이 있어야 하며, 기존 ENV 완료 조건은 유지한다.

Git 관련 ENV-01·02·09 및 C02·04·06의 운영 기준은 [Git 작업 전략](git-workflow.md)을 따른다. 2026-10-23 전략을 문서화했으며 실제 기준 커밋·worktree 생성·원격 CI·보호 규칙 적용은 별도 미완료다.

ENV-10의 채널·전송 또는 ENV-11의 요청된 검증이 미완료이면 해당 항목을 미완료로 남긴다. 구성 초안 또는 비활성 설정만으로 ENV 완료를 선언하지 않는다. 사용자가 명시적으로 범위를 조정하면 이유·영향·후속 작업을 기록한 뒤 통과 조건을 변경한다.

## 함께 진행할 수 있는 작업

### ENV 내부 순서

1. ENV-01·02로 경계와 변경 절차를 정한다.
2. 그 경계 위에서 ENV-03 역할 계약과 ENV-09 작업·결정·인계 체계를 함께 구체화한다.
3. 역할 계약 확정 후 ENV-04 모델·비용 정책, ENV-06 도구·권한 목록, ENV-08 격리 설계를 함께 작성한다.
4. 도구·격리 계약을 합의한 뒤 ENV-05 Skills와 ENV-07 Hooks·감사를 구성한다. 개발 Slack ENV-10은 수신자·권한 결정 후 인계/감사 형식에 맞춰 별도 진행할 수 있다.
5. 모든 설정을 통합한 뒤 ENV-11의 승인된 대표 흐름 검증과 완료 판정을 한다.

ENV 진행 중 A의 미정 질문과 B의 공개 근거를 수집할 수 있다. 이는 이후 설계의 입력 준비이며 ARC 확정이나 애플리케이션 구현 착수는 아니다.

### ARC 내부 순서

1. A01~06·ARC-01·02에서 요구·정상/장애 시나리오를 정한다. 자동 환전 필수 여부는 증권사 결정 전에 정한다.
2. 범위가 정해지면 B01~06·ARC-08의 외부 기능/제약 조사와 ARC-03의 경계 초안을 함께 작성하고, 결과를 상호 반영해 공통 계약 초안을 합의한다.
3. 계약 초안을 기준으로 ARC-04 데이터·원장, ARC-05 운영 AI, ARC-06 주문·위험, ARC-07 격리·보안, ARC-09 운영·보고를 나눠 설계할 수 있다. 공통 필드·상태 전이는 주 담당이 통합한다.
4. ARC-10에서 계약 간 모순·장애 경로·미확정을 정리한 후 ARC-11로 작업별 소유권·산출물·완료 기준을 확정한다.

## 의존관계 보정과 병행 금지 구간

### 조회와 주문을 나눠 순환 의존 제거

기존 I 전체는 F·G06 완료를 기다리지만 F05는 증권사 조회를 필요로 했다. 이를 다음 하위 산출물로 나눈다. `-R`/`-W`는 기존 ID의 범위 표시이며 새로운 독립 완료 항목이 아니다. 원래 ID는 필요한 하위 산출물이 모두 완료돼야 완료 처리한다.

| 하위 범위 | 포함 | 선행조건 |
|---|---|---|
| I01-R·I02-R·I08-R | 인증/호출 제한 기반, 잔고·미체결·체결·현금 조회, 시장·환경별 조회 지원표 | B01, ARC 공통 계약, D01·03·05·07, E01·02 식별/시간 계약 |
| I01-W·I02-W·I08-W 및 I03~07 | 주문·정정·취소, 상태 전이·실행자·정책 검사·복구, 주문 지원표 | 조회 기반, F 기본·대사, G06, 승인 계약, 해당 환경 격리 |

F01은 데이터 공급자 완성 전에 계약을 정할 수 있다. F02·03·08의 로컬 계산·이벤트 처리는 합성 데이터로 진행할 수 있다. F04·06의 평가 완성에는 E03·05의 가격/환율이, F05의 대사 완성에는 I 조회 경로가 필요하다. 증권사 조회 실패·불완전 조회를 성공한 빈 결과로 취급하지 않는다.

### 순서를 반드시 지킬 항목

- ENV 통과 전 ARC 최종 확정·애플리케이션 구현, ARC 계약 확정 전 금융 핵심 구현을 시작하지 않는다.
- 공통 스키마·금액 계산·주문 상태기계·DB migration을 여러 작성자가 동시에 변경하지 않는다.
- 승인·위험 검사·원장·대사가 준비되기 전에 자금을 사용하는 주문 경로를 연결하지 않는다.
- 모의와 실전은 단계적으로 승격한다. 모의 성공을 실전 권한으로 해석하지 않는다.
- 같은 계좌의 주문은 하나의 유효 실행자만 제출한다. 연구·보고의 병렬 실행과 계좌 주문 제출의 동시성은 구분한다.
- 사용자 운용정책·승인 범위 변경과 그 변경을 전제로 한 자동 주문을 동시에 진행하지 않는다.
- 검토 대상 버전이 바뀌면 변경 범위에 영향을 받는 검토·검증 결과를 다시 판단한다.

### 병행 작업 운영 규칙

실제 병렬 agent 실행은 별도 명시 요청이 있을 때만 한다. 현재는 병행 가능성을 정의했다. 실행 시 기본 구성은 조사·검토 2~3개 작업과 주 작성자 1명이며, 총 agent 수는 저장소 규칙의 2~6개 범위를 따른다. 재귀 위임은 하지 않는다. worktree는 변경 충돌을 줄이는 수단이며 비밀정보 접근 격리를 대신하지 않는다.

각 작업은 `ID / 입력 계약 버전 / 담당 / 소유 파일 / 허용 도구 / 선행조건 / 산출물 / 완료 증거 / 막힌 결정`을 기록한다. 계약 변경은 주 담당에게 먼저 합치고 관련 작업에 전파한다. 같은 파일의 동시 수정이나 실제 계좌·큐·DB를 공유하는 검증은 병행하지 않는다.

## 지금 시작할 작업과 사용자 결정 시점

초기 착수 묶음 ENV-01·02·03·09의 기준과 설정은 마련됐다. 현재는 ENV-04·06·07·08의 잔여 범위, ENV-10 개발 Slack, ENV-11 전체 흐름 확인을 마무리한다. 기존 공개 조사와 통과한 권한·제어 검증은 재사용하고 미확인 사항만 보완한다. 실제 실행 순서는 상세 목록과 최신 작업 카드에 따라 이어간다.

| 결정 시점 | 필요한 사용자 결정 | 그전에도 가능한 일 |
|---|---|---|
| 유료 AI·도구/환경 설정 전 | 개발 예산, 허용 공급자·도구, 호스팅·격리 제약 | 역할·입출력·권한·비용 상한 구조 설계 |
| ENV-10·11 완료 전 | 개발 Slack 수신 범위·전송, Hook 신뢰·검토 방식의 실제 조건 | 이미 요청된 로컬 합성 검증, 알림 형식·설정·인계 준비 |
| ARC 요구·증권사 확정 전 | 주식/ETF·세션·주기, 위험·승인 정책, 자동 환전 필수 여부 | 현재 KIS 권고·키움 대안의 미확인 기능 목록 정리 |
| 계좌/데이터 연결 전 | 계좌·공급자 이용조건·자격증명 주입·조회 범위 | 합성 데이터 개발과 인터페이스 문서화 |
| 모의 주문·통합 검증 전 | 테스트·모의 API 실행 범위, 관찰 기준 | 코드·검증 계획·합성 입력 준비 |
| 소액 실전 전 | 계좌·전략·금액·기간·손실 한도·중단 조건 | 모의 결과와 미해결 위험 정리 |

계획의 주 경로는 **ENV → ARC → 공통 기반 → 조회·원장 → 검증된 목표안 → 모의 주문 통합 → 지속 모의 → 소액 실전 → 자동운영**이다. 일정은 담당 가용시간·예산·검증 범위와 모의 관찰 기준이 정해진 뒤 산정한다. agent 수만으로 기간 단축률을 약속하지 않는다.

## 구현 마일스톤

ENV와 ARC 완료 후 공통 기반 → 데이터·증권사 조회·원장 → 전략·연구 AI → 모의 주문·통합 검증 → 지속 모의 → 소액 실전 → 정책 범위 자동운영 순으로 진행한다. 단계별 선행조건과 병행 범위는 위 실행 순서를 따른다. 보고와 운영 감시는 각 단계의 관찰 수단으로 함께 붙인다.

1. 계좌·자산 가시화: 실제 잔고와 맞는 포트폴리오·일일 보고.
2. 연구·제안: 출처와 재현 가능한 백테스트가 있는 목표안.
3. 모의 자동매매: 주문부터 원장·보고까지 이어지는 운영.
4. 소액 실전: 승인된 제한 자금으로 실제 비용과 운영 확인.
5. 자동운영: 승인 정책 안에서 분석·리밸런싱·주문·검토·보고 실행.
