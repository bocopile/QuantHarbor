# 제품 작업 목록 보완 검토 — 2026-10-27

상태: 제한 Sol/high 일반 검토와 Astra/high 보안 검토를 순차 수행하고 root가 통합했다. 사용자가 대시보드 외 추가 필요 항목의 검토를 요청했다. 공개 계획·계약·작업 카드의 범위를 검토했으며 코드 전수 감사나 실행 검증이 아니다. 검토 당시 제안은 큐·계약·권한을 변경하지 않았다. 이후 사용자 채택으로 [EXEC-DEC-002](decisions/EXEC-DEC-002-product-delivery.md)와 [확장 계획](product-delivery-plan.md)에 반영했다. 금융 권한·기존 완료 증거는 유지한다.

## 판정

금융 처리·위험 통제·복구 규칙은 이미 상당히 상세하다. 주요 보완점은 사용자가 설치하고 설정한 뒤 매일 운영할 수 있도록 기능을 연결하고, 그 사용 흐름을 완료 기준으로 만드는 데 있다. 기존 계약에 있는 기능을 새 기능으로 중복 집계하지 않는다.

대시보드는 J06에 있지만 Q22의 실제 완료 범위는 텍스트/JSON CLI다. 또한 [operations-v1](contracts/operations-v1.md:34)은 초기 승인을 대화형 로컬 CLI·보호 IPC로 한정하고 웹 승인을 비활성화한다. 앞선 대화에서 제안한 웹 승인·제어 화면 연결은 기존 계약의 단순 UI 추가로 처리할 수 없다. 조회 화면과 금융 행동을 분리해 설계하고, 웹 승인을 선택할 경우 인증·권한·요청 검증 계약과 검증 범위를 먼저 갱신해야 한다.

조회 화면도 표시 데이터·현재 조회 권한·브라우저 캐시/저장·접근 종료 후 잔존·접속 범위를 설계한다. 원격 공개·공유는 포함하지 않는다. 조회 화면 열림·자동 새로고침은 제어 세션 생존이나 금융 권한 갱신이 아니다. 인증된 제어 연결의 종료/단절, 기존 주문 추적, 수동 재개는 기존 [세션 계약](contracts/operations-v1.md:50)을 따른다.

## 이미 포함되어 있어 중복 추가하지 않을 영역

수수료·환율·기업행동·정정, 데이터 지연/누락, 전략 비교/백테스트, 승인 만료·철회, 중복 주문·부분체결·상태불명, 중단·복구, AI 근거/비용/권한, 비밀정보 분리, 백업·감사·보존, Git 작업 전략은 기존 A~M·계약·정책 관문에 있다. 개별 구현·실제 운영 완료 여부는 각 카드로 판단한다. 모니터링과 백업을 새 기능처럼 다시 추가하지 않고 GAP-04/06/07에서 사용 흐름과 검수만 보강한다.

## 적용 순서 제안

1. GAP-09와 대시보드 사용 범위를 정리해 기존 Q에 하위 산출물·증거를 매핑한다. 현재 Q27의 결함 수정/완료 판정을 건너뛰지 않는다.
2. 대시보드 요구·와이어프레임, GAP-01/02/03/08의 사용 흐름을 설계한다. 비밀번호·실계좌 없이 문서/합성 화면으로 구체화할 수 있다.
3. Q27 판정 후 Q28에 GAP-04/06/07과 로컬 조회 화면의 연결 작업을 구체화한다. 웹 제어 도입을 선택하면 GAP-03 계약 변경을 선행한다.
4. Q29에서 설치부터 최초 합성 계좌 도입·분석·승인·주문·보고·종료·복원까지 기존 CLI 승인 경계를 유지한 동일 제품 사용 흐름으로 검수한다. 웹 승인·철회·중단·재개 버튼은 도입 결정·계약 갱신·해당 검증 전까지 비활성이다. 각 경계의 기존 전문 시험도 유지한다.
5. 사용자 입력 가능 시 GAP-05 목록으로 실제 연결에 복귀하고, 기존 승인과 PG/SG 충족 범위에서 검증한다. 실제 관찰이 필요한 Q30 이후는 합성 성공으로 대체하지 않는다.

모바일 앱·클라우드 공개 서비스·다중 사용자·구독 결제·소셜 기능·자동 환전·추가 증권사는 초기 개인 로컬 제품의 필수 보완으로 제안하지 않는다. 별도 범위 결정 없이 기존 개발에 추가하지 않는다.

설치·초기 진단은 합성/공개 설정으로 검수하며 실제 비밀 입력·API 연결은 기존 관문 충족 후 진행한다. 비밀번호 입력 보류를 유지한다. 복원 시 옛 승인·세션·nonce 실행 권한을 무효화하되 주문·체결·unknown·예약·소비 이력은 보존한다. 재설치·용량 정리를 운영 자료 삭제 승인으로 해석하지 않고, 백업에도 기존 보존·삭제 절차를 적용한다.

## 검토 범위와 미실행

- 실제 수행: 공개 문서 대조 및 근거 수집, 독립 일반 검토 8개 묶음과 보안 문구 보완 6개를 root가 위 9개 묶음에 통합. 제품 배포와 사용자 안내는 별도 산출물로 분해하고, 실제 연동은 신규 기능 대신 기존 잔여 추적으로 분류했다. [검토 증거](evidence/product-gap-review-2026-10-27.json).
- 미실행: 제품 코드 전수 검토, 설치·브라우저·성능·실계좌 시험, 외부 공급자의 최신 지원/권리 재확인.
- 기존 전체 18/36·로컬 7/10은 기존 범위의 항목 집계다. 이 제안을 포함한 제품 전체 완성률로 환산하지 않았다.
