# QuantHarbor 전체 작업 목록 — 8패널 팀 운영 기준

정의일: 2026-10-29. 작업: [PLAN-team-work-list-2026-10-29](tasks/PLAN-team-work-list-2026-10-29.md). 입력 기준: 로컬 main `80403ab3b8ef322e7d38e8554b42f263bb37cbae`와 이번 대화에서 작성한 미커밋 분석/상태 기록.

## 1. 이번에 정의하는 범위

목표는 **설치하고 시작할 수 있는 로컬 제품에서 데이터·자산·연구·후보·사용자 승인·합성/모의 주문·대사·보고·중단/복구까지 연결하고, 실제 근거와 별도 결정에 따라 실전·자동운영으로 진행하는 것**이다. 개발 AI 패널과 제품 안에서 동작할 투자 AI는 서로 다른 구성이다.

이 문서는 사용자 요청에 따른 전체 목록과 담당/순서 정의다. 목록 작성 당시에는 개발 보류를 유지했다. 이후 사용자가 분석 완료 후 실제 작업 재개를 지시했으며 [현재 상태](status.md)와 [Q27 재개 카드](tasks/EXECUTION-resume-2026-10-29.md)에 실제 착수/결과를 기록한다. 정의된 계획과 실제 완료는 구분한다.

- **36개 실행 묶음 Q01~36:** 순서·통합 범위. 기존 [전체 큐](../config/ai/execution-queue.json)를 유지한다.
- **110개 원래 작업 ID:** ENV·ARC·A~M의 요구 범위. 이 문서 끝에 전부 색인하고 [원래 세부 정의](execution-checklist.md)에 연결한다.
- **12개 제품 필수 하위 작업:** P28 8개, P29 2개, RETURN 2개. Q28~30의 완료 조건에 포함되므로 36개에 더하지 않는다.
- **Q27 잔여 8단계:** 미완료 실행/예약/복구 작업을 처리하기 위한 하위 절차. 새로운 상위 큐가 아니다.
- **재개 준비 5항목:** 팀 기동과 입력/상태 정렬을 위한 절차. 제품 기능 완료 수에 포함하지 않는다.

순서는 `개발 환경 → 요구·계약 → 기반·데이터 → 원장·연구·승인 → 실행·복구 → 제품 조립/화면/설치 → 통합 → 실제 연결 복귀 → 지속 모의 → 실전 분리/진입/평가 → 정책 운영/확장`이다. 의존관계가 충족되지 않은 작업을 패널이 비어 있다는 이유로 시작하지 않는다.

## 3. 8개 패널의 고정 책임

입력→절차→반환·권한·중단/재개는 [패널별 실행 설계](team-section-design.md)를 따른다. [배정](templates/team-assignment.md)·[반환](templates/team-result.md)으로 역할 실행을 식별한다. 사용자의 후속 지시로 설계 완료 후 실제 작업 재개가 허용됐다. 위 보류 표는 목록 정의 당시 상태이며 최신 실제 진행은 [status](status.md)와 Q27 재개 기록을 따른다.

| 패널 | 책임 | 반드시 반환할 것 | 쓰기/실행 경계 |
|---|---|---|---|
| 01 총괄 LEAD | 준비된 작업 선택, 배정, 공개 근거 조회, 계약·상태·큐·증거 통합, 사용자 결정 취합 | 입력 버전·소유 파일·판정·남은 관문·다음 담당 | 공통 파일 통합 담당. 구현자에게 소유권을 넘긴 동안 같은 파일 동시 수정 금지 |
| 02 조사 RESEARCH | 코드/공식 자료 조사, capability·권리·버전 미확인 정리 | 출처/파일·확인일·사실/제안/미확인 | 읽기 역할. 실제 계정·주문·외부 전송 없음 |
| 03 설계 ARCHITECT | 계약·상태 전이·실패/복구·경계 설계 | 제안·대안·영향·구현/시험 조건 | 문서/코드 직접 통합은 root. 필요한 설계 제안만 반환 |
| 04 구현 BUILD | 확정 계약의 기능·결함 수정 | 실제 diff·자기 확인·미실행·영향 | 배정 파일의 단독 작성자 |
| 05 일반 검토 REVIEW | 정확성·회귀·요구/계약 누락 독립 검토 | 발생 조건·영향·파일/심볼·해결 여부 | 읽기 역할. 작성자 대화를 reviewer로 재명명하지 않음 |
| 06 보안 검토 SECURITY | 권한·비밀정보·승인·환경·egress·예약/복구 경계 검토 | 위험·반례·강제 지점·확인/추정 구분 | 읽기 역할. 실제 비밀값 감사는 별도 범위 |
| 07 검증 VERIFY | 요청한 검사·재현·결과 판독 | 명령·환경·입력 버전·PASS/FAIL/NOT RUN·정리 | 대상 코드를 임의 수정하지 않음. DB/결과 쓰기는 지정 범위만 |
| 08 작업 보드 BOARD | 현재 작업·담당·단계·차단 사유·증거·다음 행동 표시 | root가 확인한 요약 | AI 역할이 없는 상태 표시. 현재 수동 갱신이며 상시 감시 서비스 아님 |

전문 worker 한 명·writer 한 명·재귀 위임 금지를 유지한다. 8개 패널은 8명 동시 실행을 뜻하지 않는다. 실제 역할 기동은 [ENV-DEC-004](decisions/ENV-DEC-004-role-execution.md)의 제한된 별도 부모 실행 경로를 사용한다. 모델 설정과 실제 가용성/로드를 구분한다.

## 4. 개발 재개 직후의 준비 5항목

아래는 재개 시 실행할 준비 목록이다. 이번에 모델/권한 프로브나 제품 검사를 실행하지 않았다.

| 순서 | 작업 | 담당 | 완료 조건 |
|---|---|---|---|
| 1 | 현재 사용자 재개 범위·보류·기존 승인과 실제 입력 버전 확인 | 총괄 | 기존 허가 재질문 없이 대상·제외·검증 요청 범위를 카드에 고정 |
| 2 | README·status·작업 보드·작업 카드·큐의 현재/과거 구분 정렬 | 총괄 | 로컬 main 병합·Q27 보류·전체/로컬 포인터 의미가 일관됨. 과거 증거를 덮어쓰지 않음 |
| 3 | HEAD·미커밋 diff·소유/보호 파일 manifest·필요한 작업 branch/worktree 고정 | 총괄 | 검토/검증이 같은 입력을 식별하며 기존 사용자 변경 보존 |
| 4 | 필요한 역할의 명시 모델/제한 프로필·도구·Hook 적용 확인 | 총괄, 필요 시 보안/검증을 한 명씩 | 기존 증거와 변경된 실행 환경을 대조. 변경 영향에 필요한 확인만 수행, 권한 오류의 무제한 우회 없음 |
| 5 | 단일 worker 배정·반환·타임아웃/중단 인계 절차 준비 | 총괄 | 작업 ID·입력·소유 파일·허용 도구·결과 경로·중단 조건이 명확. 반환/종료만으로 성공 추정 금지 |

기존 cmux 패널을 실제 worker와 연결하는 기동·수동 인계는 이 준비에 포함된다. 자동 메시지 라우터·무인 dispatcher·예약 감시·자동 재부팅 복구는 현재 필수 제품 범위로 새로 추가하지 않는다. 필요하면 별도 요구로 정의한다.

## 9. 사용자 결정과 외부 권한의 준비 시점

이 목록은 지금 모든 결정을 한 번에 요구하는 설문이 아니다. 이미 받은 결정/승인은 정확한 기존 범위에서 재사용한다.

## 10. 모든 작업의 착수·검토·완료 규칙

- **착수:** 작업 ID·사용자 범위·선행·입력 SHA/비커밋 manifest·소유/보호 파일·도구/외부 영향·산출물·검증 요청 범위가 고정돼 있어야 한다.
- **인계:** 조사/설계는 근거와 제안, 구현은 diff와 자기 확인/미실행, 검토는 고정 입력의 지적, 검증은 실제 명령/환경/결과/정리를 반환한다.
- **검토:** 금융 계산·원장·승인·주문·권한 경계에는 일반 검토와 필요한 보안 검토를 연결한다. 읽기 역할은 코드를 고치지 않는다.
- **검증:** 계획에 검사 항목이 있다는 이유만으로 실행하지 않는다. 실행 요청과 대상/환경 범위 안에서 필요한 검사를 수행하고 무관한 성공 검사를 반복하지 않는다.
- **완료:** 산출물·같은 최종 입력의 관련 검토/검증·미해결 중요 결함 판정·남은 실제 관문·인계 갱신을 대조한다. exit 0·창 종료·담당자의 “완료” 메시지는 단독 근거가 아니다.
- **상태:** 대기/진행/검토 필요/보류/실패/완료와, 검사 PASS/FAIL/NOT RUN을 구분한다. 이번 계획 작성 완료는 제품 작업 완료로 집계하지 않는다.
- **중단/재개:** 마지막 반환·프로세스·미커밋 파일·DB 상태와 불완전 실행을 확인하고 작업을 재배정한다. 외부 주문/전달을 맹목 재전송하지 않는다.
- **운영 실적:** 지속 모의·소액 실전·월간/연간 결과는 실제 기간과 관찰이 필요하다. 개발 세션 안에서 코드 작성으로 대체하지 않는다.
- **일정:** 고정 범위·자원·검증 규모·관찰기간을 정한 뒤 산정한다. 현재 패널 수나 큐 수로 완료 날짜·배속을 약속하지 않는다.
