## 1. 사용자·문제·버전 가치

**사용자.** 한국 거주 개인 한 명이 본인 계좌만 운용한다 [가정·미결정, ND-09: 가정이 깨지면 전문가 확인이 선행].

**문제.** 현재 합성 금융 코어(원장·목표안·투자 AI·승인·실행)는 있으나, ① 무엇을 얼마나 보유할지 정하는 정책 계층이 비어 있어 후보가 사용자의 포트폴리오 의도에서 나오지 않고, ② 마감되지 않은 실행 안전 항목이 있으며, ③ 사용자가 처음부터 끝까지 한 흐름으로 쓸 제품 경로가 없다.

**이번 버전의 가치(제안).** 사용자는 합성 로컬 환경에서 다음을 끝까지 수행한다.

1. 자신의 포트폴리오 정책을 입력하고 모순·누락을 즉시 안내받는다.
2. 자산 상태와 제안 근거(출처·가정·반대 근거·미확인)를 이해한다.
3. 주문 후보를 후보마다 직접 승인하거나 거절하고, 언제든 신규 제출을 중단한다.
4. 주문·체결·대사 결과와 장애·복구 상태를 확인하고 조건이 충족될 때 직접 재개한다.

**성공 조건(제안).** §7의 수용 기준이 합성 입력에서 모두 충족되고, 실제 연결로 돌아가기 위한 미완료 관문이 사용자에게 보인다(RETURN-01). 시험 개수·PR 수는 성공 조건이 아니다.

## 4. 정책·목표안·승인·시간의 업무 의미

### 4.1 포트폴리오 정책

- **의미.** 정책은 자산배분(시장·현금·허용 범위), 유니버스·ETF 허용 방식, 포지션·집중도 한도, 리밸런싱 규칙, 환전·현금 하한, 낙폭 대응을 하나의 버전 불변 묶음으로 가진다. 값만 있고 단위·계산 기준·행동이 없으면 유효 정책이 아니다 [계약, policy-gates: 자금·집중도·거래 한도·손실·전략·승인·복구 묶음]. 주문 빈도·정정취소 상한은 기존 정책 관문 계약에 없으며 이 문서의 새 정책 항목이다 [제안].
- **정책 값은 사용자가 정한다.** AI는 값을 채우지 않는다. 필수 값이 비어 있으면 후보를 만들지 않고 사유를 설명한다(임의 기본값 금지) [채택].
- **변경.** 정책 변경은 새 버전이며 기존 승인·미체결에 대한 영향(유지/무효/재승인 필요)이 변경 전에 표시된다 [채택].
- **허용 폭 단위.** 자산군은 절대 %p, 종목은 상대 %로 구분하는 방향이며 1 lot 비중보다 좁아 실현할 수 없는 폭은 "실현 불가"로 표시한다 [채택 방향]. **단위와 값은 모두 ND-03 결정 후에 확정**하며 그 전에는 요구로 고정하지 않는다 [미결정, ND-03].
- **주문 패턴 제한.** 시세조종·허수호가로 읽힐 수 있는 빈도·정정취소 패턴은 정책의 상한으로 막는다 [제안].

### 4.2 목표안

- **첫 배분 방식(기준선).** 사용자 지정 고정 비중과 허용 폭, 종목은 동일 비중 기준선, 기준통화 KRW. 역변동성·위험균형·최소분산은 비교 후보이며 기본값이 아니다. 합성 평가용 기준선이며 운용 채택이 아니다 [미결정, ND-01].
- **목표의 종류.** 전체 목표와 부분 변경을 구분하고, 전체 목표에서 누락된 종목은 임의 청산하지 않는다. 누락의 의미가 모호하면 보류한다 [계약, SC-08].
- **기존 권한과의 관계.** 새 목표는 기존 승인·미체결을 자동 대체하지 않는다. 대체 관계와 추가 승인 필요 여부를 표시한다 [계약, SC-08].
- **정수 주식.** 잔여 현금은 목표 대비 부족이 큰 종목 순으로 재배분하고, 최소 거래금액 미만 포지션은 만들지 않으며, 남은 현금은 보고한다 [채택].
- **비중의 분모.** 비중은 현금을 포함한 계좌 총자산(기준통화 KRW 환산)을 분모로 하며 시장 비중과 현금 비중의 합은 100%다. 시장 내부의 종목 비중은 해당 시장 비중에 대한 조건부 비중으로 따로 정의한다 [제안].
- **불변식.** 현금 포함 전체 비중 합 = 100%(시장 비중+현금), 주문 후 현금 ≥ 0, 한도 준수. 같은 입력·버전이면 같은 결과. 해가 없으면 임의로 고치지 않고 차단 사유를 설명한다 [제안].

### 4.3 리밸런싱

- **결과는 세 가지다.** 후보 생성 / 거래 없음 / 차단. "거래 없음"도 정상 결과이며 이유(허용 폭 안, 최소 거래금액 미만, 쿨다운 중)를 설명한다 [제안].
- **트리거.** 정기 일자이거나 허용 폭 이탈일 때만 후보를 만든다. 정기·허용 폭·하이브리드 중 무엇을 쓸지(트리거 방식 선택)는 [미결정, ND-02]이고, 결합 규칙(밴드 절대/상대, 현금 포함 여부, 회전율 편도/총합과 윈도, 쿨다운)과 복귀 목표(목표점/밴드 경계)의 값은 [미결정, ND-03]이다. **결정 전에는 트리거를 구현 대상으로 확정하지 않는다.** ND-02·03은 사용자가 정하는 값이며 FU-08의 합성 비교 결과를 입력으로 쓰지 않는다(§8.1 순환 해소 규칙).
- **우선관계 [제안].** 쿨다운·최소 거래금액·회전율 상한이 트리거와 충돌하면 거래하지 않는 쪽이 우선한다(안전 방향). 최종 우선순위는 ND-03에서 확정한다.
- **2단계.** 매도대금에 의존하는 매수는 매도 체결·결제·대사와 가용금 확인 뒤에만 후보로 만든다. 미래 매도대금으로 매수 여력을 만들지 않으며 매수는 확인된 가용금만 쓴다. 이미 확인된 가용금만으로 가능한 매수는 이 제약을 받지 않는다 [채택·계약, REQ-03].
- **환전.** 시스템은 환전하지 않는다. 수동 환전 필요액만 표시한다 [확정, REQ-03].

### 4.4 위험 축소

이 절 전체는 **ND-04 결정에 종속**된다. 사용자가 reduce-only 허용을 채택하기 전에는 아래를 요구로 확정하지 않으며, 현재 계약대로 한도 초과 시 위험 증가 주문은 차단된다. 구현은 사용자 결정, Q27 판정(FU-01), 계약 개정(`schema_version`)이 모두 선행된다. 범위 채택(PLAN-DEC-001)은 허용 결정이 아니다.

- **ND-04 채택 시 적용 [미결정]:** 한도 초과 상태에서 위험을 **증가**시키는 주문은 차단하고 위험을 **줄이는** 후보는 허용한다. 위험 감소를 입증하는 입력·유효 승인·필수 정책 검사는 그대로 요구한다 [제안].
- 다중 위반은 모두 진단하되 진단은 저장소에 쓰지 않는 읽기 전용이며, 축소안은 별도 후보로 만든다. 승인은 사용자 몫이다 [채택].
- 자동 청산은 하지 않는다. 낙폭 단계 수·임계값·자동 청산 여부는 [미결정, ND-04].

### 4.5 거래비용

- 거래대금 비례 수수료·세금은 연도·시장별 버전 스케줄로 표현하고, 금액·호가는 정수 원 또는 Decimal로 다룬다 [채택].
- **경계.** 이 버전은 **거래 비용의 표현과 비교**까지다. 양도소득세 등 세무 계산 확정은 범위 밖이다. 거래세 첫 스케줄 값 후보(2026-01-01 이후 코스피·코스닥 합계 0.20%)는 세무 확인 전에는 확정하지 않는다 [미결정]. 문서별 지위가 다르다: 작업 목록은 원문 미확인, 델타 분석은 1차 확인으로 정정했다. 이 문서는 원문 재확인 전까지 "미확인 후보값"으로 취급하고 시험에서는 fixture 값으로만 쓴다.

### 4.6 시간과 세션

- **확정.** 정규장만, 분석·후보 생성 기본 15분 [확정, A-DEC-002]. 15분 유지 여부는 [미결정, ND-20]이며 결정 전에는 15분을 따른다.
- **주기 분리.** 분석 주기, 데이터 신선도, 주문 제출, 리밸런싱 판단은 서로 다른 주기다. 분석 간격을 신선도 기준으로 쓰지 않는다 [계약, SC-06].
- **잠자기·긴 작업 후.** 누락된 분석 slot을 몰아서 실행하지 않고 사용자 활성 세션 안에서 다음 slot부터 재개하며, 기존 주문 추적을 우선하고 금융 재전송은 자동으로 하지 않는다. 누락 분석의 표시 방법은 [제안].
- **연장장 [제안].** 미국 연장 거래·NXT 같은 시간대는 "자료·규칙 표현 보유"와 "실행 허용"을 구분한다. 표현은 합성 fixture 범위에 한정하며 실데이터 수집이 아니다. 실행은 정규장만이라는 확정 범위를 유지하고 연장장 실행은 별도 결정 없이는 허용하지 않는다.
- **시장 규칙.** 호가단위·가격제한폭·세션·휴장일은 출처·확인일·확신도를 가진 외부 데이터이며, 보유하지 않은 연도·구간은 실패 처리한다 [채택].
- **주문 수명.** 미체결 소멸 시점·이월을 합성 어댑터의 상태 머신 입력으로 반영하고 중복 주문을 막는다(합성 fixture 한정) [제안].

이번 버전은 판단 오류와 사용자 개입(거절·철회·중단)을 기록하고, 예상 비용과 실제 비용의 차이를 다음 검토에서 볼 수 있게 하는 데까지만 한다. 정책 비교는 시도 횟수·설정 조합 수·유효 수·실패 수를 분리해 append-only로 남기며, 합성 결과는 구조 검증의 근거로만 쓰고 정책 값 선택의 근거로 승격하지 않는다. 소표본(예: 월 1회 리밸런싱의 연 12결정)의 성과 우위는 "판정 불가"가 기본값이다 [채택]. 자동 학습·전략 자동 반영은 범위 밖이다.

### 8.2 정책 관문

- **PG-02:** 합성 범위의 비교 명세는 이미 확정됐다(RESEARCH-DEC-001·comparison-spec-v1). 실제 자료 평가와 전략 채택 권한은 아니며 이 버전도 부여하지 않는다 [계약].
- **PG-01·03·04·05:** 미완료이며 이 버전이 해소하지 않는다. PG-01(모의 API 전 자금·위험·승인 정책), PG-03(모의 주문 전 전략·기간·리밸런싱 선택), PG-04(지속 모의 전 운영), PG-05(실전)다.
- 이 버전의 정책 값은 합성 평가용이며 실제 운용값이 아니다 [계약]. 실제 연결·제출·실전 진입은 해당 관문 전까지 차단된다.

### 8.3 버전 완료 조건 [제안]

다음 버전은 합성·로컬 범위에서 §7.2의 AC-01~27이 모두 충족되고(§9.2 추적표로 FR·UI·NFR이 모두 AC에 연결됨), §7.1의 NFR이 판정되며, 실제 연결로 돌아가기 위한 미완료 관문(PG-01·03·04·05)이 사용자에게 보일 때 완료로 표기한다. 미실행 항목이나 "판정 보류"(예: NFR-08 수치 미확정) 항목이 있으면 분리 표기하고 부분 완료로만 쓴다. 통합 판정(AC-14·15)은 다른 필수 FU의 수용이 모두 같은 소스 버전에서 충족된 뒤 수행한다(FU-14는 FU-15를 포함한 필수 FU 전부가 선행). 실행 안전 마감(AC-16) 판정 없이 위험 축소·비용 개정과 통합 판정을 완료로 표기하지 않는다. ND-04 결정 전에는 AC-05를 "판정 보류"로 둔다. **증거 구분:** 기존 구성요소의 과거 통과 기록(예: 제품 836·실제 DB 86건 PASS)은 이 버전의 새 요구 수용 증거가 아니며, 같은 소스 버전에서 새 AC를 직접 확인한 근거만 수용으로 표기한다. 해당 증거는 `q27_complete=false`와 관측 공백 6건을 명시하므로 Q27 완료로 확대하지 않는다.

### 8.4 위험

- 실행 안전 마감 지연이 계약 개정과 통합 판정의 선행이다.
- 합성 시뮬레이션은 구조 검증용이며 정책 값 선택의 근거가 아니다.
- 이 문서는 사용자 인터뷰 없이 기존 문서와 채택된 작업 목록에서 도출했다. [채택]은 범위 채택이지 세부 승인이 아니다.
- 계약 상태 표기가 문서마다 다르다: `product-read-v1`·`product-artifacts-v1`은 머리글이 최종 확인 전·미구현인데 제품 전달 계획과 후속 작업 기록은 검토·수용 완료로 적는다. 이 버전은 어느 쪽도 완료 근거로 쓰지 않으며, FU-12 착수 전에 계약 머리글을 "설계 채택/부분 구현/수용 완료"로 갱신하는 정리가 선행한다 [제안].
- 새 동작(정책·구성기·리밸런싱·시도 원장·비율 비용·FR-07)의 완성 계약은 아직 없다. 각 FU 착수 시 계약 개정(`schema_version`)으로 만든다.
