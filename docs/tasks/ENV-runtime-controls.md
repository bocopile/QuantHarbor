# ENV-runtime-controls — 로컬 검증의 시간 제한·재시도·감사

- 상태: 로컬 검증기 제어 구현·검증 완료, ENV 전체 감사는 미완료
- 단계·선행조건: ENV-04·07·11, 기존 합성 권한 검증기
- 요청 근거: 사용자의 반복 허가 없이 전체 순차 진행 요청
- 담당·독립 검토: 주 담당 1명, 자기 검토
- 소유 파일: 검증 스크립트, 제어 경로 테스트, 개발 작업 정책, 본 카드와 관련 상태 기록
- 허용 범위: 합성 입력의 로컬 실행과 비민감 결과. 외부 메시지·계좌·유료 runner 없음
- 검증: 시간 초과·기동 실패·잘못된 출력·한도 오류가 통과로 오인되지 않는지 확인하고 실제 프로필 검증 수행

## 적용할 제어

- 새 유료 API runner의 추가 예산을 0으로 두고 생성하지 않는다. 기존 Codex 계정의 청구 한도나 월 예산을 강제한다는 의미는 아니다.
- 합성 검증 하위 명령은 최대 15초, 명령 묶음은 120초이며 자동 재시도는 0회다. 설정값의 범위를 검증한 뒤 실행한다.
- 묶음 예산을 소진하면 남은 항목은 실행하지 않고 실패로 기록한다. fixture 생성·정리까지 포함한 전체 프로세스의 강제 종료 시간은 아니다.
- 감사 결과에는 실행 ID·설정/정책/스크립트 해시·항목·시도 횟수·소요 시간·결과만 남긴다. 원시 stdout/stderr·환경변수·파일 내용은 넣지 않는다.
- 이 기록은 검증기의 완료 보고다. 프로세스 강제 종료에도 보존되는 전체 도구 감사 로그나 Hook 실행 증거가 아니다.

## 인계

- 실제 프로필 검증 10/10과 제어 경로 테스트 5/5가 통과했다. 테스트는 예산 소진 시 미실행, timeout 비재시도, 기동 실패 비통과, 원시 출력 제거·잘못된 payload 거부, 잘못된 한도 거부를 확인한다.
- [완료 증거](../evidence/env-runtime-controls-2026-10-20.json)에 실제 결과와 입력 해시를 기록했다. 기존 ENV-validation 증거는 이전 검증기 버전의 기록으로 보존했다.
- 기존 Codex 계정 청구 한도·전체 도구 감사·Hook 신뢰·Slack 전송은 이 구현으로 완료되지 않는다.
- 사용자는 반복 진행 허가를 요구하지 말라고 명시했다. 이미 요청된 로컬 작업의 단계별 허가는 다시 묻지 않는다. 기존 ENV 완료 순서도 유지한다.
- 후속 [ENV-durable-audit](ENV-durable-audit.md)에서 고정 로컬 검사를 감싸는 시작·종료·실패·중단 기록과 미완료 판독을 구현하고 독립 검증했다. 기존 validator 자체의 최종 JSON과 별개이며 전체 도구 감사로 확대하지 않는다.
