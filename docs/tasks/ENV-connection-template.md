# ENV-connection-template — 공개 설정 틀과 로컬 연결 정보 분리

- 상태: 완료 — 설정 틀·비추적 로컬 사본 준비 범위
- 단계·선행조건: ENV-01·02·09 보완. Q04 대기 중에도 가능한 환경 설정 문서화
- 요청 근거·실행 범위: 사용자가 공통 예제의 최초 Git 반영과 실제 연결 정보의 별도 파일·ignore 분리에 동의하고 전체 작업 진행 요청
- 담당·독립 검토 여부: root 작성·검증·통합, qh_security_reviewer 공개 파일 3개 독립 읽기 검토
- 입력 계약·설정 버전: 보안 정책, AP-01 승인 범위, 연결 예제 schema_version 1
- 소유 파일: `config/connections.example.yaml`, `config/connections.local.yaml`(비추적), `config/README.md`, 본 카드·상태 문서
- 허용 도구·외부 변경 범위: 로컬 템플릿 작성·제외 규칙 확인. 기존 파일 덮어쓰기·실제 키 조회·외부 연결·commit·push 없음
- 검증 범위: 예제 구문·로컬 사본 동일성·파일 권한·실제 Git 제외 결과. API 동작 검증 아님
- 시간·비용: 외부 호출·신규 지출 없음

## 산출물과 완료 기준

- 공통 예제에는 빈 식별값과 환경변수 참조 이름만 넣는다.
- Slack·증권사·데이터·운영 AI API는 비활성, 주문·예약·투자 보고도 비활성으로 시작한다.
- 새 로컬 사본만 소유자 읽기/쓰기 권한으로 만들고 기존 로컬 파일이 있으면 보존한다.
- 공통 예제는 ignore되지 않으며 실제 로컬 경로는 ignore되는지 확인한다.
- 실제 설정 로더는 ENV 이후 구현 단계의 작업으로 남긴다.

## 인계

- 실제 변경: 공개 YAML 예제·사용 문서와 비추적 로컬 사본을 작성했다. 로컬 사본은 배타 생성했고 실제 값은 넣지 않았다. 기존 ignore 규칙을 그대로 사용했다.
- 실제 확인: YAML 파싱, 모든 연결 비활성, 빈 식별값, 모의 기본값·주문/예약/투자 보고 비활성, 초기 사본 동일성, mode 0600, Git local 제외·미추적과 example 비제외를 확인했다. [비민감 증거](../evidence/env-connection-template.json)에 기록했다.
- 독립 보안 검토: 공개 파일 3개의 설계에서 실질 결함 없음. 로컬 사본·자격증명은 검토자에게 읽게 하지 않았으며 파일 권한·Git 제외 검증은 root 실행이다.
- 미실행: 설정 로더·API 연결·실제 credential 입력·Git commit/push. 최초 커밋에 포함할 틀 준비와 실제 커밋을 구분한다.
- 다음: Q04로 복귀. 사용자가 직접 Hook 신뢰 등록 후 알리기로 했으므로 root는 신뢰 상태를 변경하지 않는다. 완료 알림 후 실제 Hook 실행→Q05→Q06 판정을 이어간다.
