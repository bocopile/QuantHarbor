# A-input-preparation — 초기 제품 범위의 사용자 결정 준비

- 상태: 완료 — 1차 요구 입력 수집·정리 범위. A01~06 전체·ARC 확정 아님
- 단계·선행조건: ENV 중 허용된 A 요구 질문 준비. Q07 착수·ARC 확정이 아님
- 요청 근거: 전체 순차 진행, 총괄 AI 팀 운영, 필요한 결정만 사용자에게 취합 요청
- 담당: root 통합, 조사 역할의 공개 문서 읽기 자문. 작성자는 root 한 명
- 입력: vision, plan, execution-checklist A01~06, 승인 목록, 기존 증권사 선택 조사
- 소유 파일: 본 카드, docs/requirements-input.md, docs/team-dashboard.md, docs/status.md
- 허용 범위: 공개 문서 읽기·미결정과 설계 영향 정리·질문. 코드·금융 계약 확정·실제 계좌/비밀정보/외부 mutation 없음
- 검증: 사용자 요구와 제안·미정을 문서상 구분. 테스트 실행 대상 없음
- 비용: 기존 구독 범위. 유료 공급자·계좌 연결 없음

## 산출물과 완료 기준

- 이미 확정된 요구와 필요한 사용자 결정·결정 시점·영향을 한 문서에 연결한다.
- 1차로 상품 범위·분석 주기·자동 환전 필요 여부만 질문한다. 사용자가 답하기 전 기본값을 확정하지 않는다.
- 자금·손실 한도·주문 권한은 미정으로 남기며 이번 질문을 거래 권한으로 해석하지 않는다.
- 조사 담당의 공개 문서 자문은 별도 제한 CLI 실행이나 격리 실증으로 표시하지 않는다.

## 인계

- 2026-10-23 세 가지 요구 질문을 비동기로 요청했다. 답변은 승인 목록 AP-04의 요구 입력으로 연결하고 실제 거래 승인과 구분한다.
- 사용자 답변: 한국·미국 개별 주식+일반 ETF 초기 포함, 장중 반복 분석·후보 생성, 사용자 수동 환전·시스템 현금 조회. 요구 입력과 A-DEC-001에 기록하고 vision·broker-selection·architecture·approval-register·status의 현행 설명을 맞췄다.
- 실제 조사: `requirements_scout`(Luna/high)의 공개 문서 자문이 미정 간격·세션·ETF 유형·주문 권한 경계를 반환했다. 후속 `visibility_reviewer`(Sol/high)의 공개 문서 독립 검토에서 실질 요구·권한 확대 문제 없음. status의 Hook 조회 시점 표현 1건을 지적해 계획 정리 당시와 후속 재조회를 구분하도록 수정했다.
- 확인: 변경 문서의 로컬 링크 존재와 Hook 증거 JSON 파싱 성공. 제품 테스트·API 재조회·금융 코드 구현은 실행하지 않았다.
- Q04는 같은 날짜 실제 조회에서도 Hook enabled 6·untrusted 6·오류/경고 0이다. 사용자 직접 등록 선택을 유지한다.
