# TEAM-bootstrap — orchestrator와 순차 AI 팀 구성

- 상태: 완료 — 팀 구성·명시 모델 순차 위임·독립 검토·지정 로컬 검증 범위. ENV 전체는 미완료
- 요청 근거: 2026-10-20 사용자가 AI 팀 생성·역할 분리·모델/Reasoning Level 설정·orchestrator 운영·잔여 작업 순차 배정·필요 시 중간 승인 요청을 명시
- 선행조건: 기존 ENV 설정·110개 상세 작업·36개 순서·사용 가능한 모델 목록 확인
- 담당: `/root` orchestrator. 전문 역할은 순차 위임하며 재귀 위임 없음
- 소유 파일: orchestrator가 `.codex` 역할/부모 설정, AGENTS, 팀 정책·실행 큐·팀 문서·공통 상태 통합
- 입력: 현재 AGENTS·plan·execution-checklist·security, 로컬 모델 목록, 공식 subagents 문서
- 범위: 역할별 설정, 실제 역할 위임·인계, 순차 큐, 승인 필요 항목 취합, 독립 검토·검증
- 범위 밖: 기존 ENV 완료 조건 변경, 자금·계좌·키 변경·Slack 전송·Git 외부 변경의 자동 승인
- 검증: TOML/JSON 구조, 설정 로더, 실제 위임 결과, 큐의 작업 ID·의존성·담당 대조

## 완료 기준

- orchestrator와 6개 전문 역할의 모델·추론·책임·수정 범위가 저장돼 있다.
- 현재 세션의 실제 위임 모델/추론과 파일 설정·미래 세션 설정을 구분한다.
- 주 담당만 공통 파일을 통합하고, 구현자는 배정 파일만 수정한다.
- 110개 작업을 덮는 순차 실행 큐와 필요한 사용자 결정 기록이 있다.
- 사용자 확인이 필요한 경우 작업자가 orchestrator에게 전달하며, orchestrator가 구체적인 대상·내용·영향을 준비해 질문한다.
- 별도 agent 검토를 수행하되 자기 검토와 구분한다.

## 실행 기록

모든 위임은 `fork_turns=none`, 명시 모델/추론, 역할 지침을 전달하는 `default` 경로로 시작했다. 현재 도구의 역할 목록에 프로젝트 사용자 정의 역할이 없어 선택한 경로다. 역할 TOML 자동 발견이나 공급자 측 실제 모델의 독립적인 확인을 의미하지 않는다.

| 순서 | 담당 | 실제 수행·인계 |
|---|---|---|
| 1 | qh_researcher · gpt-6-luna/high | ENV 잔여·문서 충돌·선행조건을 읽고 근거 반환 |
| 2 | qh_architect · gpt-6-astra/high | 역할·비용·승인 바인딩·권한 경계 제안. AP-09와 승인 버전/범위 반영 |
| 3 | qh_implementer · gpt-6.1-sol/high | 팀·큐 검사기와 합성 회귀 테스트 작성 |
| 4 | qh_reviewer · gpt-6.1-sol/high | 별도 읽기 검토. 완료 포인터와 승인 참조 검사 결함 2개 발견 |
| 5 | qh_implementer | 두 결함 수정, 증거 상대 파일 존재·경로 탈출 검사 보강. 합성 테스트 13개 및 실제 검사기 통과 보고 |
| 6 | qh_reviewer | 수정 후 독립 재검토. 기존 두 결함 해소, 검토 범위에서 신규 결함 없음. 테스트 직접 실행은 하지 않음 |
| 7 | qh_security_reviewer · gpt-6-astra/high | Q28 투자 보고에 개발 알림 AP-01을 연결한 오류 발견. orchestrator가 별도 미승인 AP-10으로 수정 |
| 8 | qh_security_reviewer | AP-10 등록·Q28 연결·전송 제한을 재검토하고 지적 해소 확인 |
| 9 | qh_validator · gpt-6-luna/high | 이력 미상속 상태에서 문서로 인계 파악. 팀/큐 검사 exit 0, 합성 단위 테스트 13개 통과(exit 0) |

공통 설정·문서·상태는 orchestrator가 통합하고 구현 담당의 소유 파일은 `scripts/check_ai_team.py`, `tests/test_ai_team.py`로 제한했다. 전문 worker는 순차 배정했다. 실제 조회 로더는 프로젝트 기본 `gpt-6.1-sol/high`, 열린 child 상한 6, 기존 권한 프로필 2개, Skill 3개 활성·오류 0을 반환했다. Hook은 여전히 `untrusted`다.

## 최종 확인과 인계

- 독립 검증 담당 실행: `python3 -B scripts/check_ai_team.py` → 6명·36개 큐·110개 원 작업 ID 정합, exit 0.
- 독립 검증 담당 실행: `python3 -B -m unittest discover -s tests -p test_ai_team.py` → 13개 통과, exit 0.
- 일반 검토 2건·보안 검토 1건을 수정하고 각 검토자가 재검토해 해소를 확인했다.
- Q28의 AP-10 의미 연결은 보안 재검토와 검증 담당의 문서 확인으로 검증했다. 단위 테스트는 승인 참조의 형식·등록을 검사하며 Q28의 특정 승인 ID를 고정하지 않는다.
- 이력 미상속 검증 담당은 문서로 현재 ENV 단계·AP-01/02/09 대기·ENV/금융 작업 미완료를 식별했다. 이는 새 agent 인계 확인이며 부모 클라이언트 재시작이나 Hook 실행 확인은 아니다.
- 입력 설정·검사기 해시와 선별된 로더 결과는 [팀 구성 증거](../evidence/team-bootstrap-2026-10-20.json)에 저장한다. 원시 대화·개인 식별값은 포함하지 않는다.
- 다음 담당은 orchestrator다. 후속 [ENV-development-budget](ENV-development-budget.md)에서 AP-09 재허가 요구를 정정하고 독립 검토 후 Q02의 역할·실행 상한 명확화 범위를 완료했다. 현재 Q03 도구·격리 → Q04 Skills·Hook·감사 → Q05 Slack → Q06 ENV 판정 순서를 따른다. 그 이후에만 ARC로 넘어간다.

## 절차 이탈과 검증 한계

- 설계 담당이 읽기 준비 중 비민감 문서의 임시 사본을 `/tmp`에 생성했다고 자진 보고했다. 저장소 변경은 없지만 읽기 전용 지침의 이탈이다. 역할 지침이 OS 쓰기 차단을 제공하지 않는 실제 사례로 기록하고 ENV-06/08 역할 격리는 통과 처리하지 않는다.
- 입력한 모델/추론과 agent의 정상 응답은 확인하지만 실제 공급자 모델 식별·사용량·과금의 독립 증명은 없다.
- 110개 ID 커버와 36개 큐의 형식 검사로 각 원래 작업의 전체 완료를 주장하지 않는다.
- Slack·Hook 신뢰 응답, 전체 도구 감사·역할 격리·전체 재개 검증이 남아 있다. 기존 구독의 추가 지출 없는 팀 사용에는 재허가를 요구하지 않는다. TEAM 작업의 완료와 ENV 전체 완료를 구분한다.
