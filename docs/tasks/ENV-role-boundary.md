# ENV-role-boundary — 제한된 부모 환경에서 역할 실행 검증

- 상태: 완료 — Q03의 별도 부모 실행 접근·MCP 노출·역할 경로 범위. ENV 전체 미완료
- 관련 작업: ENV-06·08·11. 현재 direct subagent의 역할 이름만으로 격리가 생기지 않는 한계를 확인한 후의 보완
- 요청 근거: 전체 작업 순차 실행·역할별 모델 배정·로컬 합성 검증에 대한 기존 사용자 요청
- 담당: orchestrator가 경로를 준비하고 전문 worker가 실행 중이지 않을 때만 합성 모델 검증을 수행
- 입력: `.codex/config.toml` 권한 프로필, CLI 도움말, 공식 권한·subagents 문서, ChatGPT 로그인 상태
- 소유 파일: orchestrator가 초안을 작성한 뒤 보안 지적 수정은 구현 담당에게 `scripts/validate_role_boundary.py`, `tests/test_role_boundary.py`만 위임. orchestrator는 본 카드·비민감 증거 관리. 보안 검토 담당은 읽기만 수행
- 허용 범위: 이미 로그인한 Codex 구독에서 한정된 검증. 새 API 키·결제·계좌·외부 전송·Hook 신뢰 우회 없음
- 검증: 고정된 합성 파일의 허용 읽기·금지 쓰기·지정 비공개 경로 거부. 실제 비밀정보는 만들거나 열지 않는다.

## 확인 사실

- 현재 direct subagent는 부모 환경의 권한·MCP를 상속하며 custom role 파일로 별도 샌드박스를 지정할 수 없다.
- 설치된 CLI는 `exec --ephemeral`, `--ignore-user-config`, 명시 모델·설정 override, 구조화된 최종 출력 옵션을 제공한다.
- `codex login status`는 ChatGPT 로그인을 확인했다. 신규 API 키를 입력하거나 인증 파일을 복사하지 않는다.
- 최초 harness는 기존 권한 프로필을 별도 부모 CLI에 명시하고 앱·플러그인·MCP·웹·추가 agent 기능을 끄도록 작성했다. 아래 실행 결과에서 실제 성공과 후속 경로 확정을 구분해 기록한다. 자동 권한 상향과 Hook 신뢰 우회는 사용하지 않는다.
- 제한: 모델 턴당 120초·자동 재시도 없음. 성공에는 실제 도구 실행 결과와 바깥에서 확인한 fixture 상태가 모두 필요하다.

## 완료 판정 경계

- 제한된 별도 부모 프로세스의 검증 성공을 현재 앱 대화나 이미 만들어진 direct subagent의 권한 변경으로 해석하지 않는다.
- 프로세스가 기동하지 못하면 검증 실패로 기록한다. 금지 접근 거부와 혼동하지 않는다.
- 단순 모델의 “못 한다” 답변은 거부 증거가 아니다. 실제 합성 명령의 시도·결과와 바깥에서 확인한 파일 불변 여부가 필요하다.
- 현재 읽기/쓰기 역할에 실제로 적용할 실행 경로가 확정되기 전 ENV 전체 완료로 표시하지 않는다.

참고: [공식 Subagents 권한 설명](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## 실행 결과

- 사전 보안 검토에서 프로세스 정리, 예상 밖 명령·fixture 변조, 결과 원문 노출 문제 3건을 발견해 수정했다. 독립 보안 재검토에서 해소를 확인했다.
- CLI의 `--ignore-user-config`에서 disabled MCP 항목에도 완전한 transport 정의가 필요해 고정 command·enabled=false 항목으로 수정했다. 실제 서버 연결을 활성화하지 않았다.
- 실제 CLI JSON에서 관측한 `/bin/zsh -lc` wrapper는 내부 명령이 고정 프로브와 완전히 같을 때만 허용한다. 추가 인자·다른 명령·다른 도구를 허용하는 수정은 하지 않았다.
- 최종 전용 합성 테스트 13개 통과. 실행자는 root이며 별도 테스트 담당의 실행으로 기록하지 않는다.
- 실제 읽기 전용 프로필: 공개 읽기 허용·합성 비공개 경로 읽기 거부·작업공간 쓰기 거부 확인.
- 실제 개발 프로필: 공개 읽기 허용·합성 비공개 경로 읽기 거부·작업공간 쓰기 허용 확인.
- 두 성공 실행 모두 실제 도구 1회의 started/completed·exit 0과 바깥에서의 원본 fixture 대조를 확인했다. [비민감 실행 증거](../evidence/env-role-boundary.json)에 시각·설정 해시·결과를 저장했다.
- 앞선 기동·설정·명령 표기 실패는 실패로 보존했다. 표기 수정 후에도 한 실행이 예상 밖 도구 실행으로 거부됐고 원인은 확정하지 못했다. 후속 진단에서 동일한 엄격 판독 기준으로 성공했지만 재현성을 확정하지 않는다.
- 현재 앱과 이미 생성된 direct subagent 권한은 바뀌지 않았다. 고정 프로브만 성공했으며 일반 역할 업무를 이 제한된 부모 환경으로 일관되게 실행하는 운영 경로는 아직 확정·검증하지 않았다. Q03 전체 완료와 ENV 통과로 확대하지 않는다.

## 후속 운영 경로와 노출 확인

- 앞 문단은 접근 프로브 직후의 판정이다. 이후 ENV-skill-workflow에서 실제 읽기 역할의 명시 Skill 적용·인계를 확인하고 ENV-DEC-004에서 역할별 부모 프로필과 root의 외부 조회 책임을 채택했다.
- 실제 임시 app-server thread의 qh_review 적용 및 MCP runtime 목록을 확인했다. 4개 항목 모두 disabled, 도구 0, 탐색 오류 0, 페이지 끝. 이전 CLI의 전체 내장 도구 목록을 조회한 것으로 확대하지 않는다.
- 고정 접근 경계·실제 읽기 업무·MCP 목록·운영 경로를 결합해 Q03의 완료 판정을 독립 검토에 제출한다. 최종 코드 변경의 보안 재검토에서는 추가 실행 차단 결함을 발견하지 못했다.
- 최종 일반 독립 검토에서 Q03의 위 하위 범위 완료와 Q04 진행이 타당함을 확인했다. 과거 미완료 문구의 시점을 구분하라는 문서 지적을 반영했다. 현재 앱/direct child 격리·소유 파일별 강제·모든 내장 도구 목록·전체 ENV 완료는 포함하지 않는다.
