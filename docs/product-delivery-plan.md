기준일: 2026-10-27. 사용자 전체 목록 반영·권고 순서 실행 지시로 채택. [결정](decisions/EXEC-DEC-002-product-delivery.md), [기계 판독 하위 큐](tasks/product-delivery-queue.json), [검토 근거](product-gap-review-2026-10-27.md)를 따른다.

기존 36개 상위 큐와 110개 원래 ID는 유지하고, 아래 하위 산출물을 Q28·Q29 및 실제 연결 복귀의 완료 조건에 포함한다. Q13·Q22·Q26 등의 과거 합성 완료는 당시 범위의 증거로 보존한다. 새 대시보드/실제 인증/제품 배포가 그때 완료됐다고 확대하지 않는다. 18/36과 로컬7/10은 확장된 부모 항목의 개수이며 제품 작업량 백분율이 아니다. 하위 작업은 별도로 표시하며 합산하지 않는다.

## 전체 실행 순서

Q27 완료 예약·반복 수용 수정 → Q27 실제 합성 DB·독립 검토·최종 판정 → P28-01~08 → P29-01~02 → RETURN-01 → 사용자 입력과 기존 관문 충족 시 RETURN-02 → Q30 지속 모의 → Q31 실전 격리 → Q32 진입 결정 → Q33 소액 실전 → Q34 정책 범위 자동운영 → Q35 지속 운영 → Q36 확장 결정.

worker 한 명·작성자 한 명을 유지한다. 각 단계는 설계/구현/독립 검토/검증 증거를 구분한다. 소스 버전이 변한 경우 영향을 받는 검토·검증만 갱신한다. 실제 실행 선행조건을 만족하지 못한 금융 경로는 열지 않고 가능한 공개/합성 범위를 진행한다. 비밀번호 입력은 사용자가 가능하다고 알릴 때까지 보류한다.

## 대시보드 설계 범위

초기 범위는 로컬 조회 대시보드다. 자산/현금/위험, 분석/근거/반론, 후보와 승인 이력, 주문/체결/대사, 투자 AI 진행, 운영/연결 상태를 설계한다. 개발 AI 팀 보드와 투자 AI 작업은 명확히 구분한다. 공통 표시 항목은 환경·계좌 표시용 참조·통화·기준시점·원천/버전·잠정/확정·미확인 사유다. 빈 결과·누락·0, 프로세스 종료·업무 성공, 전송·체결·대사를 혼동하지 않는다.

화면 수치/반올림은 서버 계약을 따르고 브라우저가 금융 원장을 재계산하지 않는다. 조회 endpoint/read model의 버전·정렬·페이지 완전성·갱신/오래된 응답 폐기·오류 규약을 정한다. 읽기 권한을 매번 확인하며 브라우저 캐시/저장·접근 종료·백그라운드 갱신·로컬 접속 경계를 검수한다. 조회 새로고침은 제어 liveness나 금융 승인 갱신이 아니다.

금융 승인·철회·중단·재개는 기존 보호 CLI/IPC의 인증 경계를 유지한다. 대시보드에는 상태·대상·차단 사유와 CLI 사용 안내를 표시한다. 웹 금융 버튼은 별도 계약 선택·검증 전까지 비활성이다. 이 채택은 자동 주문·외부 공개·원격 서비스·유료 제품 API 권한이 아니다.

## 사용자 결정과 통상 설계의 구분

현재 호스트를 최초 지원 대상으로 하고 기술 분할·배치·문구·필요 시험은 root가 범위 내 결정한다. 설치 방식이나 모든 내부 설계마다 허가를 묻지 않는다. 사용자 결정은 자금/위험·전략, 실제 관찰 기간/운영 목표, 새 지출/외부 전송/원격 공개/실전 권한, 기존과 다른 웹 금융 제어 도입처럼 범위나 권한이 달라질 때만 구체안과 함께 취합한다. 기존 KIS 모의 조회 승인은 유지하며 그 범위를 다시 요청하지 않는다.
