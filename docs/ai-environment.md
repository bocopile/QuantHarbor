# AI 제반환경 명세 초안

상태: 설계 초안과 후속 후보. 2026-10-20 개발 역할 6개·Skills 3개·세션 안내 Hook을 배치했다. 사용자 팀 요청 이후 명시 모델 순차 위임·독립 검토와 팀 합성 테스트 13개를 확인했다. 역할 TOML 자동 발견·기술적 격리·감사 완성·Hook 신뢰·Slack 전송은 미완료다. 실행 기준은 [개발 환경](development-environment.md), 최신 팀 증거는 [TEAM-bootstrap](tasks/TEAM-bootstrap.md), 기존 명령 프로필 검증은 [합성 검증 카드](tasks/ENV-validation.md)를 따른다.

## 개발 AI팀과 투자 운영 AI팀

개발 AI팀은 조사·아키텍처·구현·검토·인계를 수행한다. 투자 운영 AI팀은 애플리케이션의 자료·학습·전략·포트폴리오·위험 검토·보고를 수행한다. 개발 환경을 먼저 구축하고, 운영 AI는 ARC에서 정의한 경계에 따라 구현한다.

| 개발 책임 | 산출물 | 권한 초안 |
|---|---|---|
| 조사 | 공식 출처·비교·불확실성 | 읽기 중심 |
| 설계 | 요구·인터페이스·결정 기록 | 문서 작성, 운영 변경 없음 |
| 구현 | 배정 파일의 코드·설정 | 개발 영역 쓰기 |
| 검토 | 근거가 있는 결함·누락 | 읽기 중심, 독립 검토 |
| 보안 | 비밀정보·권한·공급망·격리 검토 | 필요한 범위의 읽기 |
| 검증 | 승인된 검증 결과·실패 원인 | 격리 환경 실행, 실전 키 없음 |

역할 이름이 실제 사용 가능한 모델이나 계정 권한을 보장하지 않는다. 설치된 프리셋의 고정 모델이 지원되지 않을 수 있으므로 실행 전에 가용성을 확인한다.

## 운영 AI 모델 초안

아래 표는 향후 투자 운영 AI의 평가 후보다. 현재 개발 팀은 사용자 요청으로 [역할별 모델·추론을 명시](ai-team.md)했다. 개발 팀 설정과 아래 투자 운영 AI 후보표는 별개이며 후보표를 실제 운영 배포로 읽지 않는다.

2026-10-19 조사 기준. 세부 근거는 [모델 조사](research/models-and-brokers.md)에 있다. 현재 금융 업무 성능 평가를 통과한 배치는 아니다.

| 역할 | 모델 | 추론 수준 | 출력 |
|---|---|---|---|
| 자료 분류 | gpt-6-luna | low | 문서 종류·기업·날짜·중복 후보 |
| 일일 공부 | gpt-6-luna | medium | 출처가 있는 학습 노트·가설 변화 |
| 전략 연구 | gpt-6.1-sol | high | 실험 명세·가정·반례 |
| 포트폴리오 제안 | gpt-6.1-sol | high | 목표안 설명·제약·필요 근거 |
| 별도 위험 검토 | gpt-6-astra | high | 누락 위험·반례·검토 이견 |
| 보고 | gpt-6-luna | low 또는 medium | 확정 계산 결과의 설명 |
| 장애 분석 | gpt-6.1-sol | high | 원인·복구 제안 |
| 개발 Codex | gpt-6.1-sol | medium, 중요 변경 high | 코드·설계 변경 |
| 회계·주문·한도 | LLM 없음 | 해당 없음 | 결정론적 계산·검사 |

상향은 자신감 수치가 아니라 스키마 오류·수치 차이·출처 충돌·미해결 제약으로 판단한다. 반복 실패나 증거 부족을 무한 추론으로 해결하지 않는다. xhigh는 복잡한 충돌에 제한하고 max를 기본값으로 두지 않는다. API와 Codex UI의 옵션을 동일하다고 가정하지 않는다.

## Skills

조사, 설계, 구현 인계, 코드·보안 검토, 문서 정리, 실험 설계, 포트폴리오 검토, 사용자 보고 절차를 버전 관리한다. 각 Skill은 입력, 필요한 도구, 근거 요건, 출력 스키마, 중단·보류 조건을 정의한다. 실제 운영키와 개인 데이터는 포함하지 않는다.

## MCP와 Hooks

MCP는 공식 문서·GitHub·코드 탐색·자료·포트폴리오·백테스트 조회를 업무별로 제한한다. 서버·패키지·버전·제공 도구·접근 대상·비밀정보 주입 방식을 등록한다. 임의 서버를 일괄 설치하지 않는다.

Hooks는 개발 도구 호출 점검·감사·인계 보조에 사용한다. 주문 한도와 계좌 권한은 실행 서비스에서 강제한다. Hook이 모든 도구 경로를 막는다고 가정하지 않는다.

## 실행과 작업 계약

각 작업에는 ID, 담당, 입력 데이터 버전, 출력 스키마, 허용 도구, 파일 소유권, 시간·비용 한도, 재시도·실패 상태를 부여한다. 프로세스의 성공 종료와 금융 결과의 유효성을 구분한다.

작업 상태는 대기·진행·검토 필요·보류·실패·완료로 관리한다. 큐·스케줄러·상태 저장 제품은 ARC에서 결정한다. 도구 결과나 미완료 모델 응답을 정상 제안으로 승인하지 않는다.

작업별 파일·컨테이너·권한을 격리한다. 작업 간 전달은 검증된 산출물과 버전 ID를 사용한다. 실전 자원·키·주문 도구는 개발·연구 agent에 제공하지 않는다.

## 인계와 비용

문서에는 결정·근거·미확인·다음 작업을 남기고 개인 로그를 붙이지 않는다. 실행별 모델 ID·추론 수준·지침·도구 스키마·데이터 버전·사용량·비용·검토 결과를 기록한다. 월 예산과 역할별 상한은 사용자 결정 후 설정한다.

개발용 Slack은 진행·완료·실패·승인 요청을 다룬다. 투자 보고 Slack과 메시지 유형·권한을 구별한다. 채널과 실제 전송 승인은 미정이다.
