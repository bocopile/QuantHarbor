# 첫 모의 조회 연결 준비 — Q19

상태: 2026-10-24 KIS 모의계좌1개·로컬 수동 조회1회 조건부 승인 확보. 사용자는 계좌/API 준비됨과 저장소 밖 새 암호화 영역 준비를 선택했다. 실제 연결·토큰 발급·비공개 운영 파일 생성·읽기는 미실행이다. [저장소 준비](paper-private-storage.md)를 진행하며, PG01·지원/권리·저장/주입 검증 후 실행한다.

## 제안하는 첫 연결 범위

한국투자증권 KIS 모의 환경의 사용자 소유 계좌 하나를 대상으로, 사용자가 시작한 로컬 세션에서 조회만 수행한다. 국내 보유·현금 및 주문별 누적 체결, 해외 보유·현금 및 주문별 누적 체결을 각각 정확한 요청 범위로 구분한다. 상품별 매수가능 조회는 원천 관측으로만 확인한다. 실제 지원·권리·조회 제한이 확인된 endpoint만 활성화한다.

모의 API 주소는 `https://openapivts.koreainvestment.com:29443`이며 인증용 `/oauth2/tokenP`와 명시 GET 조회 경로만 연결 후보이다. 주문·정정·취소·환전·실전 host·WebSocket·예약 실행은 이 연결안에 포함하지 않는다. 인증용 POST는 거래 주문과 별도이며 역시 AP-05가 필요하다. 공개 [명세 조사](../research/kis-read-contracts-2026-10-24.md)가 계좌별 이용 권리를 증명하지 않는다.

첫 실행은 승인된 계좌·환경·기간·목적과 endpoint별 호출 상한/간격/timeout을 결속한 1회 조회 세션으로 제안한다. 구체 상한은 계정별 현재 제한을 확인한 후 정한다. 실패 시 자동 인증 갱신·무한 재시도·실전 우회는 하지 않는다. 여러 페이지 조회 완료가 같은 시점의 계좌 스냅샷이나 대사 완료를 뜻하지 않는다.

## 연결 전에 사용자와 확정할 것

| 묶음 | 결정·확인 대상 | 공개 기록에 남길 내용 |
|---|---|---|
| SG-01 / AP-05 | KIS 모의 계좌 준비 여부, 한국·미국 주식/일반 ETF 조회 지원, 사용자 소유/이용 권한, 위 조회 범위의 연결 승인 | 승인 범위·비공개 binding 참조·확인 결과만 |
| PG-01 | 모의 총자금·시장 배분·현금 하한, 종목/업종/시장/통화 한도, 주문/일간/참여율 한도, 손실/낙폭 및 계산 기준 | 필수값·단위·기간·기준점 검증 결과와 정책 버전만 |
| PG-01 승인 정책 | 후보 유효기간·허용 가격 변화, 정책/후보 변경 시 재승인, 철회·재사용 방지, 장애 후 수동 재개 조건 | 사용자 결정 참조·검사 결과만 |
| SG-02 / 초기 운영 프로필 | 조회 결과의 개인 이용·보존 권리, 저장 기간, 암호화된 저장소 밖 운영 영역, 자격증명 주입 방식, 복원 가능한 백업 | 권리/프로필 버전·실제 검증 결과만 |

자금·한도·계좌번호·키를 채팅이나 Git 파일에 입력하도록 요구하지 않는다. 비공개 위치와 입력 경로를 먼저 확정한 뒤 사용자가 그곳에 입력한다. 실제 키를 최초 커밋하는 방식은 사용하지 않는다. 공개 예제는 빈 구조/더미 값만 유지한다. 일반 파일 권한0700/0600 확인만으로 저장 암호화를 검증했다고 표시하지 않는다.

검토용 [비활성 입력 구조](../../config/paper-onboarding.example.json)를 제공한다. 실제 값은 모두 null/빈 목록이며 활성 정책·승인·입력 검증기로 사용할 수 없다. 공개 예제를 직접 채우지 않고, 위치를 확정한 뒤 저장소 밖 사본에 사용자가 입력한다. 금액/비율에는 통화·단위·기간·평가 기준을 함께 기록해야 하며, 실제 프로필 형식과 검증은 연결 전에 확정한다. 현재 호스트 암호화 상태 조회는 볼륨 식별 오류로 확인하지 못했다.

전략은 이후 Q23 비교 결과를 보고 Q27 전에 선택한다. 현재 연결 결정에 특정 전략 채택을 묶지 않는다. 신규 비용0·사용자 수동 시작/종료·후보별 승인 등 기존 결정은 다시 묻지 않는다.

## 결정 이후 실행 순서

1. 승인 기록과 비공개 정책·권리·저장/주입 프로필을 결속하고 누락/만료/불일치를 검사한다.
2. 실제 조회 transport와 자격증명 주입 경계를 해당 확정 입력에 맞춰 구현·독립 검토한다. 순수 변환/합성 성공을 실제 egress 검증으로 대체하지 않는다.
3. 계좌별 공식 지원/유량·종료 marker·응답 shape·현금 의미 등 미확인사항을 확인한다. 확인 불가능한 기능은 비활성/불완전 상태를 유지한다.
4. 지정 모의 host/TLS·경로·환경·계좌 binding과 로그 미노출을 검증하고 1회 승인 범위에서 실행한다. 원시 응답은 승인된 비공개 영역에서만 다룬다.
5. 성공/빈 응답/부분/오류와 페이지 완료를 구분해 실제 증거를 기록한다. 사용자 화면 수치/조회 범위와의 대조 및 지원 누락을 확인하고 Q19 완료 여부를 판정한다.
6. Q19의 실제 통과 조건을 충족한 뒤 Q20 원장으로 진행한다. 미지원 기능 때문에 범위 변경이 필요하면 영향과 대안을 사용자에게 제시한다.

현재 관문은 미완료다. 이 문서는 승인 요청을 구체화하기 위한 준비 자료이며 연결 권한이나 금융 실행 정책을 부여하지 않는다.
