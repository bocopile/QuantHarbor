# QuantHarbor 전체 세부 작업과 순차 실행 준비사항

기준일: 2026-10-20. 기존 [전체 계획](plan.md)의 **110개 작업 ID**를 세부 실행 단위로 풀어 쓴다. 기능 목록의 A~M 글자 순서와 실제 실행 순서는 다르다. 실제 순서는 아래 실행표를 따른다.

2026-10-27 현재 Q01~18은 명시 범위 완료, Q19 실제 연결은 대기다. EXEC-DEC-001에 따라 로컬 Q20~26 완료·Q27 진행 중이며 실제 통합 완료와 구분한다. 사용자 채택 [대시보드·제품 운영 확장 계획](product-delivery-plan.md)의 P28-01~08·P29-01/02·RETURN-01/02를 아래 부모 작업의 필수 하위 산출물로 추가했다. 기존36개 부모·110개 원래 ID는 유지하고 과거 완료를 새 범위에 확대하지 않는다. 최신 근거는 [진행 기록](status.md), [팀 보드](team-dashboard.md), [실행 큐](../config/ai/execution-queue.json)를 따른다. 큐 개수는 작업량 진행률이 아니다.

사용자는 기존 ENV 완료 조건을 유지했고 이후 EXEC-DEC-001로 비밀번호 입력 없는 로컬 개발 선행을 명시 승인했다. 2026-10-27 EXEC-DEC-002로 대시보드·제품 운영 보완을 추가하고 같은 순차 실행을 요청했다. 이미 요청된 로컬 설정·문서·구현·합성 검증·수정의 진행 허가는 반복해서 묻지 않는다. 실제 사용자 선택·외부 전송·자금 사용·클라이언트 신뢰 조작은 대상과 영향이 정해져야 한다.

## 20. 반복 허가 없이 진행하기 위한 작업 운영

1. **작업 상태를 분리한다.** 미착수 → 준비 완료 → 진행 → 검토/검증 → 완료. 정보·권한·외부 상태가 없으면 그 이유와 해제 조건을 기록한다.
2. **작업 시작 조건을 확인한다.** 선행 ID, 입력 계약 버전, 소유 파일, 필요한 데이터/자원, 이미 정해진 권한 범위가 있어야 한다.
3. **이미 허용된 로컬 작업은 수행한다.** 문서·설정·구현·합성 검증·오류 수정에 같은 진행 허가를 반복하지 않는다. 기술적 세부 선택은 근거와 영향으로 기록한다.
4. **사용자 고유 선택을 기술 판단으로 대체하지 않는다.** 실제 자금·위험·수신자·외부 비용은 필요한 단계에 한 번 정하고 재사용한다.
5. **외부 작업은 구체화한다.** 적용 대상·내용·영향·복구 방법을 먼저 준비하고 기존 승인 범위에 포함되면 그대로 진행한다. 범위 밖 작업만 별도로 다룬다.
6. **완료에는 증거가 필요하다.** 변경 파일·입력 버전·실행 명령·결과·남은 문제를 카드에 남긴다. 설정 작성, 실제 로드, 합성 성공, 실계좌 성공을 구분한다.
7. **검토와 수정도 순차 수행한다.** 주 담당 자기 검토와 독립 검토를 구분한다. 병렬 agent나 외부 리뷰 요청을 자동 시작하지 않는다.
8. **결함은 다음 단계 전에 처리한다.** 관련 수정·재검증 후 진행한다. 이미 통과한 무관한 검사를 반복하지 않는다.
9. **상태를 갱신한 뒤 다음 준비된 작업으로 이동한다.** 엄격한 선행 단계가 막히면 완료로 꾸미거나 무단 이관하지 않는다. 그 단계 안에서 가능한 준비를 끝내고 실제 해제 조건만 남긴다.
10. **장기간 관찰은 준비와 실적을 나눈다.** 모의 관찰·소액 실전·월간/연간 보고는 한 번의 개발 세션에서 완료할 수 없다. 운영 자원과 관찰기간이 있어야 한다. 이 목록은 백그라운드 자동 실행이나 예약 작업을 생성하지 않는다.
