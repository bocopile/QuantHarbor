# 민감정보 관리 정책

## 저장소 경계

| 정보 | 관리 위치 |
|---|---|
| 코드·아키텍처·작업 목록·공개 출처 조사 | Git 저장소 |
| AGENTS·Skills·Hooks·MCP 템플릿 | 비밀값과 개인 식별 정보를 제거한 형태로 Git 저장소 |
| API 키·증권사 비밀키·Slack 토큰·서명 키 | 저장소 밖의 승인된 자격증명 저장소; 실행 시 해당 서비스에만 주입 |
| 실제 계좌번호·고객 식별자·보유·거래·개인 보고서 | 저장소 밖의 접근 제한된 운영 데이터 저장소 |
| 운영 DB·백업·로그·AI 실행 기록 | 별도 운영 영역; 접근 제한·마스킹·보존정책 적용 |
| 설정 예제·테스트 fixture | 가짜 값과 합성 데이터만 Git 저장소 |

실제 외부 저장 경로, 자격증명 관리 제품, 클라우드, 보존기간은 ENV/ARC 단계에서 결정한다. 문서 저장 과정에서 이 저장소들을 생성하거나 키를 이동하지 않는다.

## 기본 원칙

1. 개인 경로, 사용자 이름, 계좌명 등 환경 고유값을 공개 문서에 불필요하게 기록하지 않는다.
2. 실제 비밀값은 `.env.example`, MCP JSON, Skills, Hooks, AGENTS, 프롬프트, 보고서에 넣지 않는다.
3. GitHub private 저장소도 비밀정보 보관소로 취급하지 않는다.
4. `.gitignore`는 보조 장치다. 이미 추적된 파일과 과거 이력을 지우지 못하며 임의 이름의 CSV·JSON에 들어간 개인정보를 탐지하지 못한다.
5. 과거 이력·기존 파일에 대한 비밀정보 검사는 별도 승인된 작업으로 수행한다. 이번 문서화에서 검사를 완료했다고 간주하지 않는다.
6. commit 전 탐지와 CI 검사를 도입하고, 탐지 결과에도 원문 비밀값이 노출되지 않게 한다. 현재는 구현 예정이다.
7. 샘플에는 더미 값만 사용한다. 실제 데이터의 이름만 바꾸는 것을 충분한 익명화로 간주하지 않는다.

## 업무별 접근

- 수집: 허용된 공급자·수집 영역에만 접근한다.
- 연구: 버전이 고정된 데이터와 필요한 가명화 포트폴리오만 읽는다. 실전 키와 주문 도구를 주지 않는다.
- 모의: 모의 계좌·키·DB·큐만 사용한다.
- 실전 실행: 실전 키를 제한적으로 주입하고 계좌별 실행 권한·한도·대사를 강제한다.
- 보고: 확정된 조회용 결과와 필요한 메시징 권한만 사용한다.

같은 사용자 계정의 디렉터리 분리나 git worktree만으로 보안 격리가 성립하지 않는다. 프로세스·컨테이너·호스트·네트워크·서비스 계정과 자원 한도를 설계한다.

## 운영 통제 설계 항목

- 주문·원장·개인정보에 대한 최소 권한, 감사, 암호화, 보존·삭제.
- 계좌·키·환경 바인딩과 실전/모의 잘못된 조합의 기동 거부.
- 로그·모델 입력의 마스킹과 외부 AI 공급자에 제공할 수 있는 데이터 범위.
- 데이터 공급자별 저장·재배포·모델 제공 계약.
- 백업 복원·키 교체·침해 또는 유출 시 대응 절차.
- Slack 요청 검증, 승인자·계좌·제안 버전·만료·재실행 방지.

유출이 발견되면 값의 노출을 확대하지 않고 범위를 보고한다. 키 폐기·이력 재작성·외부 삭제 등은 영향을 설명하고 필요한 명시 승인을 받은 뒤 수행한다.
