팀원이 반환한 승인 요청은 사용자 승인 자체가 아니다. orchestrator가 요청을 취합하고 사람이 답한 범위·시점을 기록한다. 사용자의 변경·철회는 이후 작업에 즉시 반영한다.

## 2026-10-21 실행 기록

- AP-01 / ENV-slack v2: 구체적인 채널·메시지·후속 개발 알림 질문에 사용자가 **“해당 채널 생성과 메시지·개발 알림 전송 승인”**으로 답했다. 지정 비공개 채널 생성, 초대 없이 참가자 1명 확인, 첫 합성 메시지 1건 전송·동일 채널 읽기 확인을 완료했다. 이후 개발 알림은 승인 범위 내 수동 전송이며 정기 실행은 생성하지 않았다. 대상 식별값·메시지 링크는 저장소에 기록하지 않는다.
- AP-01 최초 시도: 포괄적인 전체 진행 요청만으로 실행하려던 채널 생성은 자동 승인 검토에서 거절됐다. 우회하지 않았고, 위 구체적 승인 후 생성·전송에 성공했다.
- AP-02 / ENV-hook-audit 최종 v2: 사용자가 **“Hook 6개 신뢰 처리 완료”**로 답했으나 실제 사용자 상태 저장소를 사용하는 클라이언트 조회도 6개 모두 untrusted였다. 완료 응답과 실제 반영을 구분하며, 신뢰 기록 직접 편집·우회 플래그는 사용하지 않는다.

승인 기록에는 `승인 ID / 작업·초안 버전 / 대상 / 사용자 응답 근거·시각 / 허용 횟수·기간 / 실행 결과`를 연결한다. 초안·대상·전송 횟수가 바뀌면 이전 승인을 무조건 재사용하지 않는다. 민감한 대상 식별값은 비공개 위치를 참조한다.
