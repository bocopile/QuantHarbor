# EXEC-DEC-001 — 사용자 입력을 미룬 동안의 로컬 순차 실행

- 날짜: 2026-10-24
- 관련 작업 ID: Q19~29, SEC-paper-vault
- 상태: 채택
- 결정 담당·요청 근거: root; 사용자 “비밀번호 입력은 나중에 하고, 지금 입력 없이 진행할 수 있는 잔여 작업부터 순차적으로 진행” 명시 지시

## 요구와 확인 사실

Q19 합성 조회 구현·독립 검증과 암호화 저장 helper 검증은 완료했다. 실제 운영 이미지 생성은 실패했고 비밀번호 입력·비공개 정책/키·계좌 지원/권리·실제 조회는 미완료다. 기존 계획은 이 실제 연결 완료까지 Q20 착수를 막았지만, 사용자가 이번에 입력 없는 작업을 먼저 진행하도록 순서를 변경했다.

## 선택과 이유

기존 36개 큐는 전체 통합 완료 기준과 실제 관문 추적에 유지한다. 별도 [로컬 실행 큐](../tasks/offline-execution-queue.json)에 Q20~29의 입력 없는 하위 범위와 증거를 기록한다. 이 큐는 예약 실행기가 아닌 인계 자료다. 기존 큐의 `current_queue_item=Q19`는 미완료 통합 관문을, 로컬 큐의 현재 항목은 실제 개발 작업을 가리킨다. 로컬 하위 완료를 원래 작업 전체 완료로 집계하지 않는다.

1. Q20 합성 이벤트 원장·현금 구분·중복 방지·재처리 및 합성 PostgreSQL 원자성.
2. Q21 합성 평가·대사·스냅샷. 실제 계좌 대사는 대기.
3. Q22 로컬 조회·자산/현금/대사 보고.
4. Q23 root가 PG02 비교용 평가 명세를 고정한 뒤 합성 기준 전략·성과/비용·시점 검증 및 비교안. 사용자 전략 채택과 실제 데이터/엔진 권리는 대기.
5. Q24 합성 정책을 명시한 목표안·후보 생성. 실제 정책 미설정은 실행 거부.
6. Q25 합성 AI 입출력·근거·예산·오류 검사. 실제 모델 활성화/성능 평가는 대기.
7. Q26 로컬 합성 승인·철회·만료·중복 방지.
8. Q27 합성 실행기·위험/예약·실패/상태 복구. 실제 모의 주문은 대기.
9. Q28 로컬 전달·감시·복원 준비. 투자 보고 전송/예약은 대기.
10. Q29 위 구성요소의 합성 통합·장애 검증. 실제 모의 통합은 대기.

각 하위 작업은 필요한 이전 로컬 산출물의 검토·검증 완료 후 시작한다. worker 한 명·writer 한 명·기존 모델/제한 프로필을 유지한다. Q30 이후 실제 관찰·실전·자동운영·확장 선택은 합성 구현으로 대체하지 않는다. 필요한 실제 의사결정만 root가 취합한다.

## 미확인과 재검토 조건

비밀번호·실제 값·연결·권리·운영 선택을 임의 설정하지 않는다. 기존 AP05 조건부 조회 승인은 유지하되 사용하지 않은 상태다. 새 네트워크 금융 호출·비밀번호 창·원격 Git·투자보고 전송을 이번 순서 변경으로 실행하지 않는다. 로컬 작업 중 새로운 설계 결정이 필요하면 기존 계약을 보존하는 추가 명세로 정리하고 독립 검토한다.
