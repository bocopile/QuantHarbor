# PLAN-DEC-001 — v2 재감사 작업 목록 전체 채택 (ND-18)

- 날짜: 2026-11-15
- 관련 작업 ID: ND-18, NX-* 53개([작업 목록](../v2-work-list-2026-11-14.md)), NZ-* 17개와 NX 변경 45건([델타 분석](../research/v2-reaudit-delta-2026-11-15.md)), EXEC-DEC-002/003
- 상태: 채택
- 결정 담당·요청 근거: 사용자. 델타 분석의 ND-18("NX 53개 중 큐에 채택할 범위는?")에 대해 사용자가 2026-11-15 "전부 채택"으로 응답했다.

## 요구와 확인 사실

- 사용자 요구: v2 분석에서 나온 작업 목록 전부를 계획으로 채택한다.
- 확인된 사실: NX 53개와 NZ 17개, 기존 NX 변경 45건은 모두 정적 분석에서 나온 제안이었고 큐에 채택되지 않은 상태였다(델타 분석 §2, R2-12). 작업 수 대비 사용자 결정 항목이 많아 시작 조건이 막혀 있었다(PDF 재분석 N-1).
- 이 결정은 정적 분석 결과의 채택이며, 테스트·실제 DB·외부 연결을 실행해 검증한 결과의 채택이 아니다.

## 선택과 이유

선택: NX 53개와 NZ 17개 전체를 계획된 작업으로 채택한다. 델타 분석의 변경 45건(승격·강등·병합·유지·폐기)도 함께 적용 대상으로 본다.

채택의 뜻과 한계:

- 채택은 "큐에 넣어 계획된 작업으로 인정"이며 착수·완료가 아니다. 각 작업은 `docs/templates/task.md`로 작업 카드를 만들 때 입력 버전·소유 파일·완료 증거를 확정한다.
- 기존 순서는 바뀌지 않는다. AGENTS.md의 최상위 작업 순서(AI 제반환경 → 요구사항·아키텍처 → 순차 구현 → 모의 검증 → 소액 실전 → 정책 범위 자동운영)와 Q27 최종 판정(NX-BASELINE-01)이 임계 경로다. 순서 변경이 필요한 항목은 별도 사용자 결정이 필요하다(ND-17 실데이터 스파이크).
- `blocked` 및 gate가 `public_data`·`paper_broker`·`live_after_separate_gate`인 작업은 채택돼도 열리지 않는다. 열리는 조건은 SG-02·SG-04·PG·AP 관문과 사용자 승인이다. 계좌 생성·키 입력·주문·자금 이동·외부 게시는 어느 작업에도 포함하지 않는다.
- 정책 값(자산배분 비율·허용 폭·회전율·낙폭 단계·통계 승격 임계값)은 여전히 AI가 확정하지 않고 사용자 결정으로 남는다.
- 새 코드는 기존 `application/target.py`·`domain/target.py`를 수정하지 않는 새 파일 추가를 기본으로 하고, 호환성이 깨지는 계약 개정은 Q27 판정 이후 target-local-v2 단일 개정 창에서 `qh-contract-change` 절차로 한다(델타 분석 §4 NX-POLICY-04/NX-TAX-COST-01/NX-PORTFOLIO-02 병합 항목).
- 활성 worker 한 명·작성자 한 명, 재귀 위임 없음, 단순 진행 허가를 반복 질문하지 않는 기존 운영 규칙을 유지한다. 시험 추가·실행은 사용자 요청이 있을 때만 한다.
- 문서를 늘리는 작업은 델타 분석의 이력 보존형 정리 규칙(새 독립 문서 상한, status 상단 현재 표)을 따른다.

대안: 3묶음(정정·결정 수집 문서 / Q27 마감 / 새 파일 추가 코드)으로 시작하는 안이 제시됐으나 사용자가 전체 채택을 선택했다.
