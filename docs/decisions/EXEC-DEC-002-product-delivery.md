# EXEC-DEC-002 — 대시보드·제품 운영 보완을 기존 순차 계획에 통합

- 날짜: 2026-10-27
- 관련 작업 ID: J06, C03/C05, D/J/M/K, Q19~35, PRODUCT-delivery
- 상태: 채택 — 계획 반영 완료, 구현·검증은 각 하위 작업의 실제 증거로 판정
- 결정 담당·요청 근거: root; 사용자 “대시보드랑 추가 보완 항목까지 전체 작업 리스트에 반영하고, 권고한 순서대로 진행”

## 요구와 확인 사실

[검토 보고서](../product-gap-review-2026-10-27.md)의 9개 보완 묶음과 OSS 화면 표본을 전체 작업에 반영한다. 기존 Q22는 CLI 보고, Q26은 합성 인증/승인 범위 완료이며 웹 대시보드·실제 사용자 인증 완료가 아니다. Q27 완료 예약·반복 수용·독립 판정은 잔여다.

## 선택과 이유

기존 36개 상위 작업과 110개 원래 ID를 보존하고 [제품 전달 계획](../product-delivery-plan.md)의 하위 작업을 Q28/Q29·실제 연결 복귀 완료 조건에 넣는다. [하위 큐](../tasks/product-delivery-queue.json)는 부모와 별도로 추적하며 합산하지 않는다. 기존 완료 범위를 소급 수정하지 않고 미완료 부모의 완료 조건을 확장한다.

순서는 Q27 판정 → 화면·사용 흐름/계약 → 실행 조립·사용자 제어·운영 → 로컬 조회 대시보드 → 설치·업데이트·안내 → 통합 검수 → 실제 연결 복귀 → 기존 Q30~36이다. worker/writer 각1, 순차 위임과 제한 프로필을 유지한다. Q27 진행 허가를 다시 요청하지 않는다.

초기 대시보드는 로컬 조회용이며 기존 CLI/보호 IPC 금융 제어 계약을 유지한다. 표본은 Ghostfolio 자산 탐색·daily_stock_analysis 분석 흐름·FreqUI 운영 가시성이고 자체 정보 구조/디자인으로 구현한다. UI용 read model/API·민감 조회/캐시·권한·의존성/자산 이용조건을 설계 후 구현한다. 프레임워크/패키지는 지금 선정·설치하지 않는다. 실제 네트워크 금융 호출·웹 금융 권한·비용·원격 공개를 이 결정으로 확대하지 않는다.

## 영향·대안·재검토

공통 금융 계약과 frozen baseline은 이 계획 변경에서 수정하지 않는다. Q28 OPS와 Q29 통합의 선행/완료 조건, 전체 계획·구현 인계·체크리스트·실행 큐·팀 보드를 함께 갱신한다. UI가 생겼다는 이유로 기존 합성/실제 관문을 제거하지 않는다. 조회 화면 갱신은 세션 생존/금융 권한 갱신이 아니다.

대안인 36개 큐 전체 재번호 부여는 과거 증거 참조를 깨뜨리므로 사용하지 않는다. 별도 완료 수치를 더해 진척을 부풀리지 않는다. 현18/36·로컬7/10은 작업 항목 수이며 확장 제품의 작업량 완료율이 아니다.

비밀번호 입력은 보류한다. 실제 연결·정책·전략·관찰 기간·웹 금융 제어·신규 지출/외부 권한 등 실제 선택이 필요한 때만 준비된 안으로 질문한다. 현재 호스트 지원·내부 구현·명세 분해는 root가 맡는다. 원래 백업·감사·보존·Git 전략은 재작성 없이 연결한다.
