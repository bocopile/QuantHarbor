# GIT-DEC-001 — 순차 AI 팀의 Git 작업 전략

- 날짜: 2026-10-23
- 관련 작업 ID: ENV-01·02·09, C02·04·06, GIT-workflow
- 상태: 채택 — 운영 기준, 후속 GIT-baseline에서 로컬 기준 커밋 적용. main 통합·원격 보호 규칙 미적용
- 결정 담당·요청 근거: 사용자의 Git·worktree·커밋·머지 전략 요청, root 통합·독립 공개 문서 검토

## 요구와 확인 사실

전략 수립 당시 main의 초기 커밋 ec56042와 기본 checkout 하나를 확인했다. 당시 후속 산출물은 미커밋 상태였고 실제 커밋·외부 Git 동작은 AP-06 미승인이었다. 전문 worker·작성자는 한 번에 한 명이며 origin의 권한·보호 상태는 여전히 미확인이다. 현재 승인·실행 결과는 아래 후속 적용 기록을 따른다.

## 선택과 이유

- 기존 작업을 보존·검토한 기준 커밋 전환을 먼저 준비한다.
- main과 짧은 작업 브랜치를 사용하고, worktree는 역할별 상시 생성 대신 작업 분리·고정 버전 재현이 필요할 때 사용한다.
- 논리적 변경별 commit·PR, 일반 PR의 squash merge, root의 통합 책임을 기본으로 한다.
- 상시 develop·역할별 영구 브랜치는 현재 순차 개발의 통합 비용을 늘리므로 선택하지 않는다. 독립 커밋 이력 보존이 필요한 경우 merge commit을 예외로 기록한다.
- 복구는 새 revert/수정 변경으로 추적하고 실제 DB·주문·외부 효과는 별도 복구한다.

상세 실행 조건·출처·대안·한계는 [Git 운영 전략](../git-workflow.md)을 따른다. 이 결정은 Git mutation 권한이나 ENV/ARC 선행조건을 변경하지 않는다.

## 미확인과 재검토 조건

GitHub 기능·권한·실제 reviewer 계정·필수 CI job은 적용 전에 확인한다. 병렬 작성, 다중 유지 버전, 장기 release 또는 자동 배포가 필요해지면 전략을 재검토한다. 전략 수립 시점에는 Git 변경을 하지 않았다. 후속 사용자 명시 승인으로 GIT-baseline의 로컬 기준 커밋 2bed4c4를 생성했다. 원격 push/PR/merge·보호 규칙·CI는 미적용이다.
