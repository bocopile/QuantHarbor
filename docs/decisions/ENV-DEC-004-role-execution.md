# ENV-DEC-004 — 개발 역할의 제한된 부모 실행 경로

- 날짜: 2026-10-21
- 관련 작업 ID: ENV-06·08·11, Q03
- 상태: 채택 — 로컬 개발 역할 범위
- 결정 담당·요청 근거: orchestrator, 사용자의 역할 분리·순차 실행 요청

## 요구와 확인 사실

- 역할 이름과 지침만으로 읽기 전용 접근이 강제되지 않는다. 현재 앱의 direct subagent는 부모 권한을 상속한다.
- 별도 부모 CLI에 qh_review·qh_development를 명시한 실제 합성 접근 검증이 통과했다. 지정 비공개 경로 읽기는 모두 거부됐고 workspace 쓰기는 개발 프로필에서만 허용됐다.
- qh_review에서 세 Skill과 상태 문서를 읽고 합성 인계를 처리했다. 도구 1회·분류 10개·입력 불변을 확인했다.
- 같은 명명 프로필·도구 비활성 설정을 적용한 임시 app-server thread의 실제 MCP 목록을 조회했다. 항목 4개가 모두 disabled, 도구 0개, 탐색 오류 0, 페이지 끝이었다. 모델 턴과 외부 도구 호출은 시작하지 않았다.
- 이것은 MCP 노출 확인이며 모든 내장 도구 목록이나 현재 앱의 도구 변경을 뜻하지 않는다. 파일·명령 경계는 실제 프로브, MCP 경계는 runtime 목록으로 각각 확인했다.

## 선택과 이유

| 책임 | 실행 경로 | 기술적 경계와 절차 |
|---|---|---|
| 조사·설계·일반/보안 검토 | 별도 부모 실행, qh_review 명시 | 파일 쓰기 거부. 공개 입력은 root가 준비 |
| 구현 | 별도 부모 실행, qh_development 명시 | workspace 쓰기 허용. 배정 파일만 수정하는 조건은 절차 통제 |
| 검증 | 읽기·판독은 qh_review, 합성 결과 작성이 필요하면 qh_development 명시 | 실제 실행 범위·입력 버전·산출물 기록 |
| 외부 근거 조회·승인·공통 파일 통합 | root | 필요한 connector만 사용, 외부 변경은 승인 목록 준수 |

각 실행에 프로필·모델·추론·작업 지시를 명시하고 apps·plugins·MCP·web·추가 agent를 비활성화한다. 별도 실행의 MCP 구성은 전역 설정의 암묵적 상속에 의존하지 않는다. CLI에서는 `--ignore-user-config`와 완전한 disabled MCP 항목을 사용하고 기존 인증을 복사하거나 바꾸지 않는다. Hook 신뢰를 우회하지 않는다.

기동·설정·권한 오류가 나면 제한 없는 direct child로 자동 대체하지 않는다. 기존 direct child들은 공개 문서의 자문·검토 경로로만 구분하고 격리 실행 증거에 포함하지 않는다. 민감한 입력·실계좌 키·주문 도구를 이들에게 제공하지 않는다.

범용 runner를 새로 만들지 않는다. root가 작업별로 명시한 제한 실행과 결과를 기록한다. 고정 검사는 기존 감사 wrapper를 사용한다. 이 결정이 모든 도구 호출의 자동 감사를 구현하는 것은 아니며 그 범위는 Q04에 남긴다.

## 미확인과 재검토 조건

- 현재 앱이나 이미 생성된 direct child의 권한을 변경하지 않았다.
- qh_development는 소유 파일 단위의 강제 쓰기 제한이 아니다. 운영 비밀정보·실전 환경 격리는 후속 단계다.
- Hook 신뢰·실행, Slack 수신, 전체 대표 흐름은 Q04~06에 남는다.
- CLI·프로필·도구 설정 변경, 새 MCP·외부 도구 필요, 권한 판정 불일치가 생기면 영향 범위를 재검증한다. 앞선 실패를 성공 증거로 덮어쓰지 않는다.
- 근거: ENV-role-boundary·ENV-skill-workflow 작업 카드와 해당 증거 JSON, env-role-capabilities.json.
